Sentry MCP lets any attacker run code inside your AI coding agent

  • Source: Tenet Security (primary research); Cloud Security Alliance research note; The Hacker News; The Next Web
  • Link: A Fake Bug Report Hijacks Your AI Coding Agent — Tenet Security
  • TL;DR: A Sentry DSN is a write-only public key baked into most front-end builds; any attacker who finds one can POST a fake error event containing arbitrary shell commands. When you ask your coding agent to fix open Sentry issues via the Sentry MCP server, it fetches those events as trusted data and cannot distinguish the injected entry from a real error. In testing, Claude Code, Cursor, and Codex all executed attacker-controlled npx commands and silently exfiltrated AWS keys, GitHub tokens, Sentry auth tokens, and git credentials to attacker infrastructure — with the developer's own system privileges.
  • What to do: Remove the Sentry MCP server from your coding agent configuration today; more broadly, audit every MCP connection that pulls from a source accepting anonymous writes (public GitHub issues, public Slack channels, ticketing systems without write authentication) — each is a potential injection point with the same attack shape.
  • Why trust it: Tenet Security scanned 2,388 organizations with exposed Sentry DSNs and ran controlled testing across more than 100 of them, observing an 85% success rate; all three major coding agents failed independently. Tenet disclosed to Sentry on June 3; Sentry added a one-string content filter for the specific tested payload and declined root-cause remediation, calling the attack class "technically not defensible" at the platform level.
  • Skeptic check: Sentry's content filter blocks only the exact tested payload string; any attacker using a different command, encoding, or markdown structure bypasses it — the filter is not a meaningful defense against the attack class.

Claude Code now blocks specific models or shell patterns in permission rules

  • Source: Anthropic Claude Code changelog
  • Link: Claude Code changelog — Anthropic
  • TL;DR: Two permission-hardening changes shipped June 15. First, permission rules now accept a Tool(param:value) syntax that matches on a tool's actual input parameters, with * as a wildcard — for example, write Agent(model:opus) to block Opus subagents from spawning, or Bash(command:rm*) to deny shell calls where the command starts with rm. Second, auto mode now runs the classifier on subagent spawns before the subagent launches, closing a gap where a subagent could be spawned, request a blocked action, and the block would fire only after the fact.
  • What to do: Run claude update to get the June 15 release; review your existing allow/deny rules and convert tool-name-only entries to Tool(param:value) form wherever you need finer-grained control — restrict which models subagents may use, and add deny rules for destructive shell patterns you didn't previously have a way to match.
  • Why trust it: Anthropic official Claude Code changelog; confirmed by multiple third-party changelog trackers (claudefa.st, claudeupdates.dev). Feature details are also visible in the Piebald-AI system-prompt tracker for the corresponding release.
  • Skeptic check: Wildcard matching semantics (anchoring, case-sensitivity, multi-token matching) are not fully documented; test new Tool(param:value) rules explicitly before treating them as a security boundary.

Agent SDK usage now billed from a separate monthly credit — opt-in required

  • Source: Anthropic Help Center
  • Link: Using the Claude Agent SDK with your Claude plan — Anthropic Help Center
  • TL;DR: As of June 15, Agent SDK calls, claude -p headless runs, Claude Code GitHub Actions, and third-party apps authenticating via your subscription no longer draw from your plan's interactive usage pool. They now consume a separate monthly dollar credit ($20 for Pro, $100 for Max 5x, $200 for Max 20x) billed at standard API rates, per user, with no rollover. Once that credit is exhausted, requests stop unless you have usage credits enabled as overflow. A one-time opt-in is required to claim the initial credit.
  • What to do: Log into your Claude account and claim the credit if you haven't; enable usage credits as overflow protection if you run long or high-volume agentic workflows; note that credits are per-user and do not pool across a team, so every team member running automated pipelines needs their own opt-in.
  • Why trust it: Anthropic's official Help Center article and developer platform announcement; the change was announced May 14 and took effect June 15 as scheduled with no documented postponement.
  • Skeptic check: The exact definition of what counts as "Agent SDK usage" versus "interactive Claude Code" is in the Help Center article; verify your specific workflow is classified correctly before assuming it falls under the new credit pool.
