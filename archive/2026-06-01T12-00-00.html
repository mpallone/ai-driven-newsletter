Claude Code removes CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE env var today

  • Source: Anthropic — Claude Code changelog (v2.1.154, May 28, 2026)
  • Link: Claude Code release notes — claudeupdates.dev
  • TL;DR: The env var that pinned fast mode to Opus 4.6 is removed as of June 1. It stops working silently — no error, no warning — so any shell config, .env file, or CI pipeline that sets it is now a no-op.
  • What to do: Search your shell configs, .env files, and CI pipelines for CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE and remove it; to explicitly pin Opus 4.6 with fast mode in an interactive session, use /model claude-opus-4-6 followed by /fast on.

Tuning the harness beats upgrading the model for rule-governed agent tasks

  • Source: Tianshi Xu, Huifeng Wen, Meng Li — arXiv 2605.22166, v1 submitted May 21 2026, v2 revised May 27 2026
  • Link: Adapting the Interface, Not the Model: Runtime Harness Adaptation for Deterministic LLM Agents — arxiv.org
  • TL;DR: When agents repeatedly fail on tasks with strict rules — enforced formats, fixed action sets, required sequences — the problem usually lives in how the harness packages observations, structures tool calls, formats error feedback, and cuts off trajectories, not in the model itself. Fixing those four harness layers, without touching model weights, reliably doubled or more than doubled task completion rates. A harness tuned on failures from one model also worked for 17 other models, which means the fixes capture structure in the task environment, not quirks of a specific model.
  • What to do: Before concluding you need a larger model, log 20–30 failure traces and check four things in your harness: (1) are observations truncated or reformatted in a way that loses key state? (2) do tool call schemas match what the environment actually expects? (3) is error feedback descriptive enough for the model to correct course? (4) are trajectories cut off before the model has a chance to recover? Fix those first.
  • Why trust it: Tested across 7 deterministic environments, 126 model-environment setting combinations, and 18 model backbones, with an average relative improvement of 88.5% on task completion rate; implementation open-sourced at github.com/Tianshi-Xu/Life-Harness.
  • Skeptic check: All 7 test environments are deterministic and rule-governed (game-like and structured domains); results likely do not transfer directly to open-ended coding tasks or free-form instruction-following where the observation space is less constrained.
