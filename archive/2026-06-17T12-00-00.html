@mastra npm packages backdoored — rotate credentials now

  • Source: StepSecurity (primary research); Socket.dev; SafeDep; The Hacker News; Microsoft Threat Intelligence
  • Link: Mastra npm Supply Chain Attack: 140+ Packages Backdoored via easy-day-js Typosquat — StepSecurity
  • TL;DR: On June 17 at 01:12–02:36 UTC, an attacker republished 141 packages in the @mastra npm scope — including @mastra/core, mastra, and create-mastra — after hijacking a contributor account. Each package gained a single new dependency: easy-day-js, a typosquat of the popular dayjs library whose latest tag carries an obfuscated postinstall hook that downloads and runs a credential-stealing remote access trojan, then deletes itself. The stealer harvests environment variables (cloud keys, LLM API keys, GitHub tokens) and cryptocurrency wallets. The attacker seeded the ground on June 16 by publishing a clean easy-day-js@1.11.21, then flipped the malicious 1.11.22 to latest minutes before the scope-wide republish. Combined weekly downloads across the affected packages exceed 1.1 million.
  • What to do: If you ran npm install on any @mastra/* package after June 16 07:05 UTC, treat that machine as compromised: rotate cloud credentials, LLM API keys, GitHub tokens, and any cryptocurrency wallet keys it could reach, then check the host for dropper artifacts. Going forward, run npm install --ignore-scripts to block postinstall hooks; pin transitive dependencies with a lockfile and review npm audit for injected packages.
  • Why trust it: StepSecurity, Socket.dev, SafeDep, and Microsoft Threat Intelligence independently documented the attack with specific npm account names (ehindero), package version numbers, and UTC timestamps. 141 affected packages identified across four sources.
  • Skeptic check: Only users who resolved the ^1.11.21 caret range to 1.11.22 — i.e., ran npm install after the malicious tag was set at 01:12 UTC on June 17 — are affected; installs locked to an earlier version or completed before that timestamp are clean.

Domain expertise, not coding skill, determines Claude Code success rate

  • Source: Anthropic Economic Research
  • Link: Agentic coding and persistent returns to expertise — Anthropic
  • TL;DR: Anthropic measured success across ~400,000 Claude Code sessions (October 2025 through April 2026) and found novices succeeded 15% of the time, intermediate users 28%, and advanced/expert users 33%. Non-engineers working on coding tasks succeeded at nearly the same rate as software engineers at the same expertise level — meaning what predicts outcomes is your depth of domain knowledge, not your coding background. The more domain expertise you bring to a session, the more work Claude does per instruction.
  • What to do: Front-load your domain knowledge into every session: write thorough CLAUDE.md files, architecture briefs, and problem context before you start, so Claude can operate with the grounding you would otherwise supply piecemeal. Treating Claude as a pair-programmer who has already read your docs gets more work done per instruction than treating it as a code-writing tool you prompt reactively.
  • Why trust it: Anthropic ran this on privacy-preserved data from ~400,000 Claude Code sessions; success was measured by verifiable outcomes (passing tests, committed work) rather than self-report. Published June 16, 2026 by Anthropic's economic research team.
  • Skeptic check: The study is first-party Anthropic research on their own product; expertise classification methodology and success criteria are not independently audited. The causal direction — whether expertise drives success or expert users simply attempt easier tasks — is not fully resolved.

Claude Code 2.1.179 stops partial responses vanishing on mid-stream drops

  • Source: Anthropic Claude Code changelog
  • Link: Claude Code changelog — Anthropic
  • TL;DR: Version 2.1.179 (June 16) fixes the most disruptive failure mode for long agentic sessions: when a connection drops mid-stream, the partial response is now preserved instead of being replaced by a raw error and discarded. It also fixes mouse-wheel scrolling in WSL2 under Windows Terminal and VS Code (a regression from 2.1.172), a Linux sandbox bug where a denyRead/allowRead glob over a large directory tree inflated the Bash tool description so much the session became unusable, and a bug preventing Ctrl+O from opening a subagent's transcript.
  • What to do: Run claude update to reach 2.1.179; if you are on Linux with a broad sandbox glob over a large directory tree and your Bash tool calls have been silently hanging, this release fixes that.
  • Why trust it: Anthropic official Claude Code changelog.

Cloudflare MCP server can't edit WAF rules; direct API fallback required

  • Source: Simon Willison (simonwillison.net, June 16, 2026)
  • Link: TIL: Cloudflare CAPTCHA on at least one ampersand — Simon Willison
  • TL;DR: When Simon Willison asked Claude Code to fix a Cloudflare WAF misconfiguration using the Cloudflare MCP server, the server's tool set didn't cover rule-editing operations. Claude fell back to calling the Cloudflare REST API directly to complete the task. The MCP server exposes some Cloudflare operations but not all; the gap only becomes visible when you hit it mid-workflow.
  • What to do: Before building a multi-step agentic workflow around any vendor MCP server, cross-reference the server's tool list against the vendor's REST API docs for your specific operations — MCP servers often cover the most common actions, not the full API surface.
  • Why trust it: Single first-hand observation by Simon Willison; no broader testing or reproducibility data.
  • Skeptic check: The Cloudflare MCP server's tool set may have expanded since this post; verify against the current tool list before assuming the gap still applies.
