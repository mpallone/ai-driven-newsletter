Claude Code v2.1.147 fixes plugin tool registration and hook pattern bugs

  • Source: Anthropic / Claude Code — GitHub Releases
  • Link: Claude Code Releases — github.com/anthropics/claude-code
  • TL;DR: v2.1.147 (May 21, 20:39 UTC) fixes three silent failures that directly affect harness engineers. First: plugin agents that declared more than one Agent(...) type in their tools: frontmatter were silently keeping only the last type — multi-type plugin dispatchers were broken for all but the last entry. Second: hook if conditions using pattern syntax like PowerShell(git push*) never matched; the only form that worked was PowerShell(*). Third: CLAUDE_CODE_SUBAGENT_MODEL was not being propagated to teammate processes spawned by agent teams, so those processes silently fell back to the default model. Also new in this release: pinned background sessions (Ctrl+T in claude agents) now stay alive when idle, restart in place when updates land, and are evicted under memory pressure only after unpinned sessions. v2.1.148 (May 22, 01:16 UTC) is a same-day hotfix for a Bash exit-code-127 regression introduced by v2.1.147.
  • What to do: Upgrade to v2.1.148; if any of your plugins declare multiple Agent(...) types in a single tools: block, verify that all types now register at runtime; review hook if conditions that use non-wildcard patterns and retest them after upgrading; if you set CLAUDE_CODE_SUBAGENT_MODEL in a multi-teammate configuration, confirm the model is now reaching all teammate processes.
  • Why trust it: Official GitHub releases page for anthropics/claude-code; v2.1.147 timestamp (2026-05-21T20:39) and v2.1.148 timestamp (2026-05-22T01:16) confirmed by direct fetch of the releases page.
  • Skeptic check: The changelog gives no indication of how many plugins used multi-type Agent() frontmatter in practice — if you never declared multiple Agent types in one block, none of these three fixes apply to you.

Open bug: subagent tools array silently drops first and last entries

  • Source: Claude Code GitHub Issues
  • Link: Issue #60237 — Sub-agent frontmatter tools: array silently drops first and last positions at spawn time
  • TL;DR: A GitHub issue filed in late May 2026 documents that when a subagent's frontmatter declares a tools: array with N entries, only positions 2 through N-1 survive at runtime — the first and last are dropped silently. A 7-entry array [Edit, Read, Write, Bash, WebFetch, NotebookEdit, WebSearch] yields a 5-tool runtime set, with Edit (position 1) and WebSearch (position 7) missing. This is a distinct bug from the multi-Agent()-type issue fixed in v2.1.147 — it affects every tool in the array by position, not the type-declaration logic. The bug is currently open and unconfirmed by Anthropic.
  • What to do: Add a preflight check at the top of any subagent that asserts its expected tools are present before beginning work; as a temporary workaround, avoid putting critical tools at the first or last position of the tools: array.
  • Why trust it: GitHub issue #60237 with specific reproduction steps and exact position mapping (reporter tested a 7-element array and documented which positions survive); multiple independent confirmations in the thread.
  • Skeptic check: Not yet acknowledged by Anthropic as of the window close; may be limited to specific subagent types or plugin contexts — reproduce in your own harness before treating it as universal.
