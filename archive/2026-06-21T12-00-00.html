Claude Code 2.1.183 blocks destructive commands in auto mode

  • Source: Anthropic Claude Code changelog
  • Link: Claude Code changelog — Anthropic
  • TL;DR: Version 2.1.183 (June 19) added three safety blocklists for auto mode: git reset --hard, git checkout -- ., git clean -fd, and git stash drop are blocked when the agent was not explicitly asked to discard local work; git commit --amend is blocked for any commit the agent did not make this session; terraform destroy, pulumi destroy, and cdk destroy require an explicit mention of the target stack before they run. Auto mode is now also available on Bedrock, Vertex, and Foundry for Opus 4.7/4.8. Claude Code now refuses to write shell startup files (.zshenv, .bash_login) and build-tool configs (.npmrc, .bazelrc, .pre-commit-config.yaml) even in acceptEdits mode without an explicit request.
  • What to do: Run claude update to get 2.1.183. If you write instructions or automations that legitimately need any of these commands, phrase the intent explicitly — "discard local work" or "drop the dev stack" — so the guard does not trip on ambiguous phrasing.
  • Why trust it: Anthropic official Claude Code changelog, June 19, 2026; DevelopersIO independently documented the v2.1.182→v2.1.183 delta with specific command lists.
  • Skeptic check: The blocklists match on detected intent from phrasing; edge cases in instruction wording may still trigger or miss the guard inconsistently until the classifiers are tuned further.

Anthropic ships zero-touch MCP access management for enterprise via Okta

  • Source: Anthropic (claude.com/blog); Model Context Protocol Blog
  • Link: Centrally manage authorization for MCP connectors — Claude
  • TL;DR: Enterprise-Managed Authorization (EMA), announced June 18, lets IT admins authorize MCP connectors through an identity provider (Okta first) once; employees inherit access on first login with no per-user OAuth consent screens. Seven providers support EMA at launch: Asana, Atlassian, Canva, Figma, Granola, Linear, and Supabase (Slack in progress). Access follows existing IdP group and role assignments — a new employee inherits every approved connector automatically on day one. Works across Claude chat, Claude Code, and Cowork for Teams and Enterprise. EMA is the first live production implementation of the MCP authorization extension declared stable the same day, which formally classifies MCP servers as OAuth Resource Servers and requires resource indicators (RFC 8707) to bind tokens to specific server URIs, blocking cross-server token replay attacks.
  • What to do: If you run Claude for Teams or Enterprise and employees currently connect MCP tools individually, configure EMA through your Okta tenant to remove per-user friction and centralize revocation. If you build MCP servers, review the updated auth spec: add protected resource metadata and validate that incoming tokens include your server's URI — tokens without it should be rejected.
  • Why trust it: Anthropic first-party blog post June 18, 2026; corroborated by Okta press release and MCP Blog post the same date; resource indicator details confirmed by WorkOS and independent security coverage.
  • Skeptic check: EMA requires Teams or Enterprise plan and a supported IdP; individual Pro users are unaffected. Only seven MCP providers support EMA at launch.

Cursor ships /automate to configure always-on agent workflows in plain language

  • Source: Cursor changelog
  • Link: Improvements to Cursor Automations — Cursor
  • TL;DR: The June 18 Cursor update adds /automate: describe the task you want to automate in plain language and Cursor configures the triggers, instructions, and tools directly in your local session. Five new GitHub event triggers were added — issue comment, PR inline comment, PR review submission, review thread resolved/unresolved, and GitHub Actions workflow completed. Slack emoji reactions can now kick off automations. Cloud agents started by automations can use computer use to produce screenshots or video demos as proof of work.
  • What to do: Use /automate instead of manually wiring triggers in the automations UI — describe what you want in one sentence and let Cursor generate the configuration. If you already use automations, add the new workflow_run_completed trigger to chain automations after CI finishes.
  • Why trust it: Cursor official changelog for June 18, 2026 (cursor.com/changelog/06-18-26).
  • Skeptic check: Computer use in cloud automations draws from Teams quota; heavy automation use may exhaust the usage pool faster than local sessions.

Codex records a macOS workflow once and replays it as an editable SKILL.md

  • Source: OpenAI Codex changelog
  • Link: Record & Replay — Codex Developers
  • TL;DR: Record & Replay (Codex 26.616, shipped June 18) lets you demonstrate a repetitive workflow on macOS and Codex turns it into an editable SKILL.md file that accepts variable inputs — a new date, a different file path — on future runs. Skills can be shared across a team, so one person's recording becomes everyone's automation. Future executions run the skill via computer use, browser actions, connected plugins, or a combination.
  • What to do: Record your most repetitive multi-step macOS workflows — creating formatted issues, filing expenses, downloading recurring reports — to produce shareable skills rather than writing new instructions each time. Share generated SKILL.md files with your team so the workflow is available to everyone without re-recording.
  • Why trust it: OpenAI first-party Codex changelog for version 26.616; TechTimes reported on it June 20, 2026.
  • Skeptic check: Requires Computer Use to be enabled; macOS-only at launch; not available in the EEA, UK, or Switzerland; limited to Plus, Pro, Business, Enterprise, and Edu subscribers.

AI browsing agents inherit localhost trust; a web page can execute code on the host

  • Source: Microsoft Security Blog
  • Link: AutoJack: How a single page can RCE the host running your AI agent — Microsoft
  • TL;DR: Microsoft researchers chained three weaknesses in AutoGen Studio's developer build into a full remote code execution path: a browsing agent running on the same machine passes a localhost trust check that normally blocks malicious external sites; auth middleware skipped verification for MCP-registered paths on the assumption that the handler would verify tokens itself (it never did); an endpoint passed a request parameter straight to a command executor with no allowlist. Any web page the agent loads can trigger arbitrary code on the host. The affected surface is not included in the PyPI release of AutoGen Studio — only teams running the source-build dev interface are directly exposed by this exact chain.
  • What to do: Do not run AI browsing agents on machines where privileged local services — database admin UIs, container orchestrators, build servers — listen on localhost without authentication. For any MCP server you build, apply auth to all paths without exception; do not assume a path prefix means a downstream handler will verify tokens.
  • Why trust it: Microsoft Security Blog, June 18, 2026; independently covered by TechRadar, CSO Online, and The Hacker News; Microsoft reports no active exploitation of this chain.
  • Skeptic check: The specific chain targets AutoGen Studio's dev build, not the PyPI package — most production deployments are not directly exposed. The broader class of attack (prompt injection via a web page leading to host-level action through a trusted local service) applies to any web-browsing agent running on the same machine as a privileged service, regardless of framework.

Claude API adds response_inclusion to drop consumed tool results from agentic loops

  • Source: Anthropic (Claude Developer Platform release notes)
  • Link: Claude Developer Platform release notes — Anthropic
  • TL;DR: New tool versions web_search_20260318 and web_fetch_20260318 add a response_inclusion parameter: set it to exclude already-consumed tool result blocks from the API response so they do not re-enter context on the next agentic turn. A new code_execution_20260521 version discloses the 90-second per-cell execution limit in the tool description itself, so Claude can budget long-running cells before hitting the limit. No beta header is required for any of these versions.
  • What to do: Update your tool version strings to web_search_20260318 and web_fetch_20260318 and set response_inclusion to drop consumed results; this reduces token cost and context window pressure in multi-turn agentic workflows without any other code changes.
  • Why trust it: Anthropic Claude Developer Platform release notes, confirmed in current June 2026 release cycle via platform.claude.com.
  • Skeptic check: The exact release date within June 2026 is unconfirmed in available sources — this update may predate the June 18 window start. Included because it appeared in current June 2026 release tracking and is directly actionable.
