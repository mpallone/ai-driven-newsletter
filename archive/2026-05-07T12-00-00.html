Claude Code 2.1.129–2.1.132: session ID in bash env, plugin URL install, gateway discovery reverted to opt-in

  • Source: Anthropic, Claude Code GitHub releases, May 2–6, 2026
  • Link: Claude Code releases — GitHub
  • TL;DR: Four things worth noting from this week's Claude Code versions: (1) CLAUDE_CODE_SESSION_ID is now injected into every bash subprocess, letting hooks and external scripts identify which session spawned them; (2) --plugin-url <url> fetches a plugin .zip from any URL for the current session, replacing the "clone and build" sharing pattern; (3) gateway model discovery — auto-populating the /model picker from /v1/models — is now opt-in via CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1 after being automatic in 2.1.126–2.1.128; (4) CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1 keeps output in your terminal's native scrollback instead of the fullscreen renderer.
  • What to do: If you write hooks that shell out, start using $CLAUDE_CODE_SESSION_ID to namespace session-specific state; gateway users who relied on automatic model-picker population need to add CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1 to their environment — the model list will have silently reverted to the default without it.
  • Why trust it: Official Anthropic Claude Code GitHub releases and changelog; versions confirmed in the npm registry.
  • Skeptic check: The gateway discovery opt-in revert could break setups silently — if your model picker stopped listing gateway models after updating past 2.1.128, this env var is the fix.

Comprehensive tests are a hard prerequisite before you trust an agent with your codebase

  • Source: Simon Willison, simonwillison.net, May 6, 2026
  • Link: Vibe coding and agentic engineering are getting closer than I'd like — simonwillison.net
  • TL;DR: As coding agents become more reliable, engineers naturally stop reviewing every line they generate — Willison calls this normalization of deviance. The agents produce code faster than humans can read it, and a comprehensive, stable test suite is what lets CI catch the mistakes when you're not watching closely. Planning before handing off to the agent is essential and pays off more at the agentic scale.
  • What to do: Before giving an agent a non-trivial task, verify CI coverage is good enough that a test failure would catch the agent's mistakes; if coverage is thin, write the tests first and let the agent build against them rather than the other way around.
  • Why trust it: Personal observation from extended production use of coding agents; no controlled study, but consistent with practitioner reports across the community.
  • Skeptic check: Confirmation bias applies — engineers who already value testing will attribute agentic success to it; no controlled comparison against low-coverage codebases under identical tasks.

Split agent memory into a vault (context) and a config (taste) to make corrections compound

  • Source: Eugene Yan, eugeneyan.com, May 3, 2026
  • Link: How to Work and Compound with AI — eugeneyan.com
  • TL;DR: Keep a ~/vault/ for project state, artifacts, and domain facts (what the agent needs to know to do the work), and a ~/.claude/-style config directory for preferences, workflows, and taste (how it should behave). Any time you correct the agent, encode the fix as a rule or skill so it doesn't need repeating. Skills are plain markdown files — a name, a trigger, and a procedure — that load on demand and function as written workflows.
  • What to do: Create a ~/vault/ with per-project subdirectories; add a skills/ directory for any operation you do more than once a week; after each agent correction, encode the fix as a rule or skill rather than re-prompting next time.
  • Why trust it: Eugene Yan is a practicing engineer at Anthropic building production recommendation systems; the workflow is drawn from his personal experience, not a controlled study.
  • Skeptic check: The system requires discipline to keep the vault current; stale or contradictory context can mislead the agent as much as no context at all.
