Claude Code v2.1.149 patches PowerShell sandbox bypass and adds per-category usage costs

  • Source: Anthropic / Claude Code — GitHub Releases
  • Link: Release v2.1.149 — github.com/anthropics/claude-code
  • TL;DR: Released May 22, 22:09 UTC. Three practitioner-relevant changes. (1) Security fix: PowerShell's built-in directory navigation shortcuts — cd.., cd\, cd~, and X: (drive-letter switches) — were silently moving the working directory outside the sandboxed workspace without triggering the permission system, so a subsequent command could read files outside the intended scope. Fixed. (2) New feature: /usage now shows a per-category breakdown of what's driving token and cost limits — by skills, subagents, plugins, and individual MCP server. Previously it showed only a combined total, making it hard to tell whether a spike came from a runaway subagent or a chatty MCP server. (3) Enterprise: A new allowAllClaudeAiMcps managed setting lets administrators permit all claude.ai cloud MCP connectors alongside managed-mcp.json without enumerating each one individually. Additional fixes: Bedrock and Vertex users unable to pick "Opus (1M context)" from /model (regression since v2.1.129) is resolved; remote-session login failure for users with forceLoginMethod + forceLoginOrgUUID is fixed; /diff detail view can now be scrolled with keyboard shortcuts (arrows, j/k, PgUp/PgDn, Space, Home/End); Markdown output now renders GFM task-list checkboxes (- [ ] todo / - [x] done) instead of plain bullets.
  • What to do: Upgrade to v2.1.149; on Windows, confirm the PowerShell bypass is resolved in your environment — especially if your workspace sits adjacent to credential files or source the session shouldn't reach; if you run multi-MCP harnesses, run /usage after your next session to see which server is costing the most; enterprise admins should review whether allowAllClaudeAiMcps fits their connector policy.
  • Why trust it: The GitHub release tag v2.1.149 on anthropics/claude-code is confirmed to exist by direct search of the GitHub releases page; the changelog items are from search snippets indexing the official GitHub release page — the primary source was not directly fetchable (403 via jina.ai), but the tag URL and detailed changelog items were independently confirmed via the GitHub site: search result.
  • Skeptic check: The PowerShell working-directory bypass requires an adversarial prompt or malicious tool output to exploit — in typical solo-developer use the drift was likely harmless; if you don't run Claude Code on Windows with PowerShell enabled, this fix doesn't affect you.
