Cursor Bugbot PR reviews now take 90 seconds and cost 22% less

  • Source: Cursor blog, June 10, 2026
  • Link: Bugbot is now over 3x faster, 22% cheaper, and finds 10% more bugs — Cursor
  • TL;DR: Bugbot's average review time dropped from ~5 minutes to ~90 seconds (90% of runs finish under 3 minutes), it finds 10% more bugs per run (0.62 vs. 0.56 per PR), and costs about 22% less ($1–$1.50/run depending on PR size). Two new features ship alongside: a /review command that runs Bugbot before you open a PR — it syncs with GitHub/GitLab and won't charge again if you open the same diff as a PR later — and a selective-review mode that limits reruns to only the diff since the last review instead of rereading the whole PR.
  • What to do: Add /review to your pre-PR checklist; if Bugbot reruns are getting noisy on CI, enable selective-review mode so it only reads what changed since the last scan.
  • Why trust it: Cursor's official blog post, June 10, 2026, with specific before/after metrics; gains attributed to harness improvements and progress training Composer 2.5, which now powers Bugbot.
  • Skeptic check: "Bugs per run" is self-reported by Cursor using their own definition of a finding; your PR size, language, and what Bugbot counts as a bug will affect whether you see similar numbers.

Tools can now suspend an agent mid-run and ask the user a question

  • Source: Simon Willison (simonwillison.net), June 10, 2026
  • Link: Release: datasette-agent 0.2a0 — Simon Willison
  • TL;DR: datasette-agent 0.2a0 introduces a ToolContext object: any tool that declares a context parameter receives it and can call await context.ask_user(...) with a yes/no, multiple-choice, or free-text question. The agent's turn suspends until the user answers; the question is persisted to a database and survives a server restart. When the user answers, the tool re-runs from the start with the stored answer replayed. The key constraint: call ask_user() before any side effects, since re-execution from the top will replay the ask. A built-in save_query tool demonstrates the pattern — it always shows the SQL and proposed name before writing anything.
  • What to do: If you're building agent tools that gate destructive or irreversible actions behind human approval, study the ToolContext pattern — it puts the pause at the tool level rather than requiring the orchestration layer to know which tools need confirmation.
  • Why trust it: Simon Willison's own release post for a library he wrote, including the exact API and behavioral spec; primary-source documentation with specific code examples.
  • Skeptic check: datasette-agent is a personal project; the suspend/resume mechanism relies on datasette's specific persistence layer — porting this pattern to another agent host requires equivalent infrastructure.

Codex now preserves oneOf/allOf in MCP schemas and adds code-mode web search

  • Source: OpenAI — Codex changelog, June 10, 2026
  • Link: Codex changelog — OpenAI Developers
  • TL;DR: Codex was silently stripping oneOf and allOf from MCP tool schemas when processing them. The June 10 update preserves these constructs and keeps more of the shallow structure when compacting large schemas. $ref/$defs structures in connector tool schemas are also preserved instead of being inlined away. Separately, code mode now supports standalone web search — agents in code mode no longer need to switch modes to perform a search.
  • What to do: If you've been flattening MCP tool schemas to work around Codex stripping complex constructs, try switching to oneOf/allOf for input validation now that Codex preserves them; test your specific schemas before relying on them in production.
  • Why trust it: OpenAI's official Codex changelog, June 10, 2026, citing specific PR numbers (#24118, #27084) for the schema fixes.
  • Skeptic check: The schema structure reaching the model does not guarantee the model interprets complex schemas correctly — validate your specific tool definitions with real inputs before treating them as production-ready.
