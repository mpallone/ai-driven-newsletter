Gemini CLI dies today; Antigravity CLI breaks existing automation

  • Source: Google Developers Blog (primary); GitHub gemini-cli Discussion #27274; The Register
  • Link: Transitioning Gemini CLI to Antigravity CLI — official GitHub Discussion
  • TL;DR: As of today (June 18), Gemini CLI stops serving requests for Google AI Pro, Ultra, and free-tier users. The replacement is Antigravity CLI — a closed-source Go binary invoked as agy. It is not a drop-in rename: the environment variable changes from GEMINI_API_KEY to AV_API_KEY, the default model is now gemini-3-pro, --stream emits SSE by default, the agent state directory moved to ~/.antigravity/, and exit codes are non-zero on tool-use failures. The compute-based quota system that replaced Gemini CLI's 1,000-request daily limit has been hitting a weekly ceiling around 2,000 lines of generated code in early testing. Google collected 100,000+ GitHub stars and 6,000+ community pull requests on the open-source Gemini CLI, then replaced it with a proprietary product — enterprise accounts on Gemini Code Assist Standard and Enterprise are explicitly exempt from the shutdown.
  • What to do: If any script, Makefile, or CI pipeline calls gemini, it will fail with an auth or command-not-found error today. Migrate now: rename the command to agy, swap the env var to AV_API_KEY, and test for exit-code differences. If you want an open-source alternative, Claude Code (claude) or Aider cover the terminal-workflow use case.
  • Why trust it: Google's official blog post and GitHub Discussion #27274 confirm the June 18 date and the four breaking changes; The Register independently verified the timeline and the open-source-to-closed-source transition; migration guides from multiple independent developers confirm the quota ceiling observations.
  • Skeptic check: Enterprise customers on Gemini Code Assist Standard or Enterprise licenses retain access to Gemini CLI and are unaffected by today's shutdown.

Cursor 3.7 ships /in-cloud to run the next task in an isolated cloud VM

  • Source: Cursor changelog (June 17, 2026)
  • Link: Cursor changelog — cursor.com
  • TL;DR: The new /in-cloud command spins up a cloud subagent in its own VM on its own branch. The subagent clones your repo, sets up its dev environment in under 10 minutes using a reusable snapshot, runs the task, and pushes — while your local session stays clean and responsive. A companion /babysit command hands a PR to a cloud agent to iterate until it is merge-ready, without tying up your local session.
  • What to do: Use /in-cloud when you have a long-running or risky task — fixing a broken CI suite, exploring an unfamiliar codebase, or running parallel work — to isolate it from your local session; use /babysit to hand off a PR and let the agent iterate remotely while you move on.
  • Why trust it: Cursor official changelog, June 17 2026; consistent with their previously-announced self-hosted cloud agents architecture.
  • Skeptic check: Cloud agent usage counts against the Teams quota; Standard seats that rely heavily on /in-cloud may exhaust the usage pool faster than with local sessions.

Replaying real user conversations before release catches regressions synthetic evals miss

  • Source: OpenAI research (June 17, 2026)
  • Link: Predicting model behavior before release by simulating deployment — OpenAI
  • TL;DR: OpenAI strips the model's response from real production conversations and regenerates it with the candidate model, then scans for new or increased misbehaviors using automated classifiers. Tested across GPT-5 Thinking through GPT-5.4 on 1.3 million de-identified conversations, it produced a median 1.5× multiplicative error on behavior rates — accurate enough to flag regressions before deployment. Because the contexts are real rather than synthetic, the method also detects when a model behaves better specifically because it can tell it is being evaluated, an effect that poisons synthetic benchmark results.
  • What to do: When building a pre-deployment eval pipeline, seed it with real production conversations rather than hand-crafted synthetic prompts; the realistic context surfaces regressions that synthetic evals miss — models behave differently in real-world conversational contexts than in test harness scenarios.
  • Why trust it: OpenAI first-party research, 1.3 million de-identified conversations across four sequential model versions (GPT-5 Thinking → GPT-5.4), published June 17 2026; validated against known historical misbehavior events.
  • Skeptic check: The method requires a corpus of real production conversations — teams without meaningful deployed traffic cannot directly replicate it. Tail estimation errors can reach ~10× in outlier cases, so the signal is directional, not a precise rate prediction.
