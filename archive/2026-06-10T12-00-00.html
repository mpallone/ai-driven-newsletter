Fable 5 is on the API: refusals return HTTP 200, not errors

  • Source: Anthropic — Claude API Docs, June 9, 2026
  • Link: Introducing Claude Fable 5 and Claude Mythos 5 — Claude API Docs
  • TL;DR: claude-fable-5 is generally available on the Claude API as of June 9, with a 1M-token context window, up to 128k output tokens per request, and $10/$50 per million input/output tokens. The biggest integration change: when Fable 5's safety classifiers decline a request, the API returns stop_reason: "refusal" with a normal HTTP 200 — not a 4xx error — along with which classifier triggered. Adaptive thinking is always on; raw chain-of-thought is never returned (set thinking.display: "summarized" to get readable thinking output). The fallbacks parameter lets the API automatically retry a refused request on Opus 4.8 instead.
  • What to do: Add an explicit check for stop_reason === "refusal" in your response-handling code before you go to production with Fable 5 — your current error handler probably won't catch it; optionally add fallbacks: ["claude-opus-4-8"] to auto-reroute refused requests without client-side retry logic.
  • Why trust it: Anthropic's official API documentation published June 9, 2026, primary source; availability confirmed simultaneously on Amazon Bedrock, Vertex AI, Microsoft Foundry, and GitHub Copilot changelogs the same day.
  • Skeptic check: Third-party benchmark numbers circulating on launch day vary significantly across evaluation setups; validate Fable 5 against your own workloads before migrating production traffic.

Fable 5 prompting: "show your reasoning" instructions now trigger a refusal

  • Source: Anthropic — Prompting Claude Fable 5, June 9, 2026
  • Link: Prompting Claude Fable 5 — Claude API Docs
  • TL;DR: Fable 5 has a reasoning_extraction refusal classifier: any instruction that tells the model to echo, transcribe, or explain its internal reasoning as output text triggers it, causing those requests to fall back to Opus 4.8. Separately, Fable 5 tends to overplan, over-elaborate, and take unrequested side actions at higher effort levels. The official guide ships a set of ready-to-paste system-prompt snippets for each failure mode: an anti-overplanning instruction, a progress-grounding instruction that tells the model to audit each status claim against an actual tool result, a boundary instruction to stop the model taking unrequested actions, and a checkpoint instruction for long autonomous runs. Effort levels (low / medium / high / xhigh / max) replace thinking-budget parameters; high is recommended as the default.
  • What to do: Before migrating any existing skill or system prompt to Fable 5, grep for phrases like "show your work," "explain your reasoning," "think step by step," or "transcribe your thoughts" — those will trigger elevated refusal fallbacks; read the model's structured thinking blocks instead of asking it to reproduce reasoning in text.
  • Why trust it: Anthropic's official prompting guide for Fable 5, published June 9, 2026; the guide explicitly cites internal testing for the progress-grounding instruction ("nearly eliminated fabricated status reports even on tasks designed to elicit them").
  • Skeptic check: Prompting recommendations are derived from Anthropic's internal test harnesses; your workload and tool schemas may produce different failure modes — run your own prompts before removing existing instructions.

Task budgets: tell the model how many tokens an agent loop can spend

  • Source: Anthropic — Task budgets, Claude API Docs, June 9, 2026
  • Link: Task budgets — Claude API Docs
  • TL;DR: The new output_config.task_budget parameter (opt-in via anthropic-beta: task-budgets-2026-03-13) lets you set a token budget for an entire agentic loop, not just one request. The model sees a running countdown injected server-side and self-regulates — finishing more quickly or summarizing findings as the budget depletes. It works on Fable 5, Mythos 5, Opus 4.8, and Opus 4.7. Minimum budget is 20,000 tokens; the budget counts what the model generates (thinking, tool calls, tool results, output), not what you resend in the payload. If your loop compacts context mid-run, pass the remaining field on the next request to carry the countdown forward.
  • What to do: Run a representative sample of tasks without the budget to find your p99 token spend per task, set that as your initial budget, and combine it with a reasonable max_tokens as a hard per-request cap — task budgets are advisory (the model may overshoot slightly) while max_tokens is enforced.
  • Why trust it: Anthropic's official API documentation, primary source, published June 9, 2026; feature is live in beta on supported models today.
  • Skeptic check: A budget set too small for the task may cause the model to refuse to start or scope down aggressively; size the budget from measured data, not a fixed default.

Fable 5 disables zero-data-retention for all Anthropic API customers

  • Source: Anthropic — Model-specific data retention, Claude API Docs, June 9, 2026
  • Link: Introducing Claude Fable 5 and Claude Mythos 5 — Claude API Docs
  • TL;DR: Fable 5 and Mythos 5 require Anthropic to retain prompts and outputs for up to 30 days to run their safety classifiers. Existing zero-data-retention (ZDR) agreements do not apply to Fable 5 traffic — ZDR still works for Opus 4.8, Sonnet 4.6, and Haiku 4.5, but not for the new model class. Anthropic states the retained data is not used for training.
  • What to do: If your organization has a ZDR agreement with Anthropic, confirm with your legal or compliance team before routing any traffic to claude-fable-5; if ZDR is a hard requirement, use Opus 4.8 as your primary model and configure claude-fable-5 as an opt-in upgrade only for workloads where the 30-day retention is acceptable.
  • Why trust it: Stated in Anthropic's official launch documentation; confirmed by multiple independent coverage sources (TechCrunch, VentureBeat, cybernews.com) citing the same Anthropic policy language.
  • Skeptic check: Whether 30-day retention with no-training commitment satisfies GDPR, HIPAA, or SOC 2 requirements depends on your jurisdiction and the specifics of your existing agreement — get explicit written confirmation from your Anthropic account team, not just the documentation.
