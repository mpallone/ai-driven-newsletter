MicroPython in a WASM sandbox is a working code-execution tool for LLM agents

  • Source: Simon Willison — simonwillison.net, June 6, 2026
  • Link: Running Python code in a sandbox with MicroPython and WASM — Simon Willison
  • TL;DR: Willison released micropython-wasm, a Python package that runs code inside a WASM-sandboxed MicroPython interpreter. Each conversation in his Datasette Agent plugin gets its own persistent interpreter — variables, imports, and functions defined in earlier tool calls remain available later in the same session. He ran adversarial prompt-injection tests against GPT-5.5 in the sandboxed environment and reports no escape so far.
  • What to do: If your agent harness has a code-execution tool that runs full Python, prototype a MicroPython/WASM replacement for any path where sandbox escape would expose sensitive data or systems — per-session state persistence means the user-experience cost is low.
  • Why trust it: Working code published on GitHub (datasette/datasette-agent-micropython), alpha release on PyPI; Willison reports direct adversarial testing against GPT-5.5 with no escape, with source and methodology described in the blog post.
  • Skeptic check: MicroPython doesn't support the full CPython standard library — code paths that depend on libraries not ported to MicroPython will fail, and the sandbox hasn't been independently security-audited.

Cursor Context Explorer shows which part of your agent config is consuming the most tokens

  • Source: Cursor — Official changelog, June 6, 2026
  • Link: What's New in Cursor — Cursor Changelog
  • TL;DR: Cursor now renders an agent's token usage as an interactive canvas, breaking it down across system prompt, tool definitions, rules, skills, and conversation history separately. A "Debug with Agent" button lets you ask Cursor to identify specific compression targets. Also in this release: multi-repo Automations (one agent run reasons across and commits to multiple repos, including running tests across all of them) and no-repo Automations triggered by external events like Slack, with five new Marketplace templates. Heads-up: Bugbot billing switches to usage-based pricing at next plan renewal after June 8.
  • What to do: Run Context Explorer on your most expensive agent sessions to see where tokens actually go before optimizing — tool definitions and loaded skills are typically the highest-ROI compression targets and are often larger than expected.
  • Why trust it: Official Cursor changelog entry dated June 6, 2026; confirmed via Releasebot aggregator and Cursor Agents Window documentation.
  • Skeptic check: Token counts in the explorer reflect the current session context, not your billed cost — if your system prompt is heavily prompt-cached, the displayed count overstates what you are actually charged.

Windsurf (Devin Desktop) now lets you permanently approve all tools on an MCP server at once

  • Source: Windsurf / Devin Desktop — Official changelog, Devin Local 2026.5.26, June 6, 2026
  • Link: Windsurf Changelog — Devin Docs
  • TL;DR: When Devin Local prompts for an MCP tool permission, you now see two new server-level options: approve all tools on that server for the current session, or permanently across all sessions. Previously only individual tool-level approval was available. Always Allow grants now persist across restarts. Devin Local also gained editor context awareness — it sees which files you have open as part of its context without you adding them explicitly.
  • What to do: Grant permanent server-level approval to trusted local MCP servers you use in every session (filesystem tools, local databases); keep per-session or per-tool approval for external, network-facing, or write-capable servers where you want to stay aware of what is being called.
  • Why trust it: Official Windsurf/Devin Desktop changelog entry for Devin Local 2026.5.26, June 6, 2026; confirmed via Releasebot.
  • Skeptic check: Permanent approval survives software updates — if an MCP server update adds new tools, those tools inherit the permanent grant automatically; audit granted permissions after any server update that changes tool schemas.
