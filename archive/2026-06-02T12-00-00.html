acceptEdits now guards shell and build-tool configs

  • Source: Anthropic — Claude Code changelog, v2.1.160 (June 2, 2026)
  • Link: Claude Code release notes — claudeupdates.dev
  • TL;DR: Claude Code's acceptEdits mode — which auto-approves all file writes, and which every dynamic-workflow sub-agent inherits — now stops and prompts before writing shell startup files (.zshenv, .zlogin, .bash_login, ~/.config/git/) or build-tool config files (.npmrc, .yarnrc*, bunfig.toml, .bazelrc, .pre-commit-config.yaml, .devcontainer/). Those files can run code automatically the next time you open a shell or trigger a package-manager command, which makes silent writes to them a code-execution risk. The same release fixes a workflow friction point: viewing a file with grep, egrep, or fgrep now counts as reading it, so the Edit tool no longer rejects edits on files you've already grepped.
  • What to do: If you use dynamic workflows or run Claude Code with acceptEdits, expect new prompts for writes to those config paths — audit each one before adding it to your tool allowlist. Remove any redundant cat or Read steps you added to scripts or skills before editing files you had already grepped.
  • Why trust it: Official Anthropic release for v2.1.160; npm publish timestamp for @anthropic-ai/claude-code confirmed "last published 8 hours ago" as of June 2, 2026, corroborated by changelog trackers (claudeupdates.dev, claudelog.com) citing the same version, changes, and date. The shell-startup change also directly addresses a security concern Anthropic flagged in the Dynamic Workflows docs (May 28): sub-agents run in acceptEdits mode and file edits are automatically approved.
  • Skeptic check: If you use only the default interactive mode — where every file write already requires one-time approval — the new shell-startup guard is redundant; the grep-read fix is the more universally useful change in this release.
