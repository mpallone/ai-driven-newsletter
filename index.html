/mcp now tells you when an MCP server connected with zero tools

  • Source: Anthropic, Claude Code changelog, May 4, 2026
  • Link: Claude Code Changelog — Claude Code Docs
  • TL;DR: The /mcp command now shows a tool count next to each connected server and flags any server that connected with 0 tools — the most common sign of a broken or misconfigured MCP server. Same update batch: bare /color (no argument) picks a random session color; --plugin-dir now accepts .zip plugin archives in addition to directories; and a new --plugin-url <url> flag fetches and loads a .zip plugin archive from a URL for the current session.
  • What to do: When an MCP-backed tool is missing, run /mcp immediately — a "0 tools" flag tells you which server is the problem without needing to dig through logs. If you distribute or share plugins, consider switching to .zip archives so users can load them with a single --plugin-url flag.
  • Why trust it: Official Anthropic Claude Code changelog entry dated May 4, 2026, confirmed by multiple third-party aggregators (releasebot.io, claudelog.com, claudefa.st).
  • Skeptic check: The 0-tool flag shows a symptom, not a root cause; a server can connect with 0 tools due to auth failure, startup crash, or capability mismatch, so you still need to inspect server logs to fix the underlying issue.

Claude Code skillOverrides adds three visibility modes for custom skills

  • Source: Anthropic, Claude Code changelog, version 2.1.128
  • Link: Claude Code Changelog — Claude Code Docs
  • TL;DR: The skillOverrides setting now accepts three modes: off hides a skill from both the model's tool list and the / command palette; user-invocable-only hides the skill from the model while keeping it available for humans to invoke via /; name-only keeps the skill visible to both but strips its description out of the context window, reducing token overhead for skills the model should just call by name.
  • What to do: For skills that are dangerous to auto-invoke (deploys, destructive refactors, irreversible operations), set user-invocable-only so the model can't fire them autonomously. For skills with long descriptions that the model rarely needs help understanding, switch to name-only to save context budget.
  • Why trust it: Official Anthropic Claude Code changelog, confirmed via third-party aggregators; no published token-budget comparison between modes.
  • Skeptic check: name-only assumes the model can infer what a skill does from its name; if your skill names aren't self-explanatory, removing the description may reduce correct auto-invocations.

Claude Code 2.1.129 breaks automatic gateway model discovery — action needed if you use a gateway

  • Source: Anthropic, Claude Code changelog, version 2.1.129, May 6, 2026
  • Link: Claude Code Changelog — Claude Code Docs
  • TL;DR: In versions 2.1.126–2.1.128, setting ANTHROPIC_BASE_URL to an Anthropic-compatible gateway would automatically populate the /model picker from the gateway's /v1/models endpoint. Version 2.1.129 makes this opt-in: you must now set CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1 or the picker won't show gateway models. Also in 2.1.129: Ctrl+R history search reverts to scanning all projects by default (fixing a regression introduced in 2.1.124 that narrowed scope to the current project); CLAUDE_CODE_PACKAGE_MANAGER_AUTO_UPDATE=1 enables background self-updates on Homebrew or WinGet installations; CLAUDE_CODE_FORCE_SYNC_OUTPUT=1 forces synchronised terminal output for terminals that auto-detection misses; third-party deployments (Bedrock, Vertex, custom gateways) no longer see in-app tips pointing at Anthropic's own surfaces.
  • What to do: Before upgrading to 2.1.129, add CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1 to your environment if you rely on gateway model discovery — otherwise your /model picker will appear empty. If Ctrl+R felt too narrow after a recent update, this version restores the cross-project default.
  • Why trust it: Official Anthropic Claude Code changelog for version 2.1.129 (May 6, 2026), confirmed by multiple third-party changelog aggregators.
  • Skeptic check: Opt-in is the safer default for deployments that don't want the picker auto-populated from a gateway; this is a conservative change, not a removal of the feature.

Three bugs in Claude Code subagent worktree isolation are fixed

  • Source: Anthropic, Claude Code changelog, May 2026
  • Link: Claude Code Changelog — Claude Code Docs
  • TL;DR: Three specific bugs in isolation: 'worktree' subagents were fixed: (1) the Agent tool was reusing stale worktrees from prior sessions instead of creating fresh ones, silently contaminating agent state; (2) subagents running inside their own worktree were being denied Read/Edit access to files within that worktree; (3) EnterWorktree was creating branches from origin/<default-branch> instead of the local HEAD, discarding unpushed commits. Separately, OTEL_* environment variables no longer propagate from the CLI into subprocess environments — OTEL-instrumented apps you run from within Claude Code no longer accidentally send traces to the CLI's exporter.
  • What to do: If you use isolation: 'worktree' in the Agent tool, update now and run a smoke test — the stale-worktree bug may have been silently reusing previous session state. If you run OTEL-instrumented services from Claude Code terminals, the telemetry bleed-over is now fixed without any config change on your part.
  • Why trust it: Official Anthropic Claude Code changelog, confirmed by third-party aggregators; no independent measurement of how frequently stale-worktree reuse caused output errors in practice.
  • Skeptic check: The changelog doesn't say whether stale worktree state produced subtly wrong outputs rather than obvious failures; if you ran intensive worktree-isolated agents before this fix, auditing those outputs manually is prudent.

Opus 4.7 /context percentage was computed against the wrong window — now fixed

  • Source: Anthropic, Claude Code changelog, May 2026
  • Link: Claude Code Changelog — Claude Code Docs
  • TL;DR: Claude Code was computing the /context usage percentage for Opus 4.7 sessions against an old, smaller context window instead of the model's native 1M-token window. This made the percentage appear higher than actual, causing autocompaction to fire earlier than needed. The fix makes Opus 4.7 sessions compute against the correct 1M window. In the same batch: /resume on large sessions is up to 67% faster and now offers to summarise a stale session before re-reading it in full.
  • What to do: If you run long Opus 4.7 sessions and have been seeing frequent autocompaction or a /context reading that seemed high relative to what you'd put in the session, update and re-check — you likely have more runway than the display was showing. If large-session /resume felt sluggish, update to get the speed improvement.
  • Why trust it: Official Anthropic Claude Code changelog, confirmed by releasebot.io; the 67% resume speed figure is from Anthropic's own changelog notes, with no independent reproduction of that number.
  • Skeptic check: The speed improvement is presumably measured on a specific session size or content type; actual improvement will vary.

Anthropic's finance agent templates show the skill + connector + subagent packaging pattern

  • Source: Anthropic news, May 5, 2026
  • Link: Agents for financial services and insurance — Anthropic
  • TL;DR: Ten ready-to-run agent templates for financial work (pitchbooks, KYC screening, earnings review, month-end close) were released, but the architecture they expose is more useful than the domain content: each template bundles three components — skills (domain-specific instructions and knowledge for the task), connectors (governed, pre-wired data access — including a new Moody's MCP app for credit and corporate data), and subagents (specialised Claude models called for specific sub-tasks, such as comparables selection or methodology checks). Each template ships both as a Claude Code / Claude Cowork plugin and as a copyable cookbook for Claude Managed Agents.
  • What to do: If you're designing multi-component plugins or skills for Claude Code or Managed Agents, treat the finance template structure as Anthropic's current reference pattern: one plugin bundles its own instructions (skill), its own data access (connector), and its own specialist sub-models (subagents). This is worth mapping against your own harness design to identify what you're handling ad hoc versus what could be packaged.
  • Why trust it: Primary source from Anthropic's news page (May 5, 2026), with secondary coverage from The Register, Let's Data Science, and Metaverse Post confirming the architecture details.
  • Skeptic check: These templates are described as reference architectures for financial services; how much they reflect Anthropic's internal production agent design versus being purpose-built for external showcase is not confirmed.

Cursor Enterprise adds model-level allow/blocklists and soft spend limits

  • Source: Cursor changelog, May 4, 2026
  • Link: Cursor Changelog — Cursor
  • TL;DR: Cursor's enterprise admin console now lets admins block entire providers or specific model configurations by speed tier and context window size. Spend limits are soft — they trigger usage alerts rather than hard-stopping work. Richer usage analytics added. The previous update (May 1) lets admins create a team plugin marketplace without connecting a code repository first, and configure install behaviour for bundled plugins (plugins can include MCP servers, skills, subagents, rules, and hooks).

Set a soft spend limit as an early-warning signal. If you've been holding off on a team plugin marketplace because it required a repo connection, that requirement is gone as of May 1.
  • Why trust it: Official Cursor changelog, confirmed by releasebot.io; no independent testing of soft-limit behaviour at the threshold.
  • Skeptic check: Soft limits mean work continues past the alert threshold; if hard budget enforcement is a compliance requirement, this feature does not meet that bar.
