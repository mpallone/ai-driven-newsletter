Migrating off 20250514 model IDs has a hidden second step: remove temperature and top_p

  • Source: Anthropic API docs (model deprecations page and migration guide); Cursor community forum; Apiyi.com migration guide
  • Link: Model deprecations — Anthropic API docs
  • TL;DR: As of today, June 15 at 9AM PT, every API call to claude-sonnet-4-20250514 or claude-opus-4-20250514 returns an error. But there is a second, less obvious breaking change: any request to Opus 4.7 or Opus 4.8 that sets temperature, top_p, or top_k to a non-default value also returns a 400 error. Swapping the model ID is not enough if your code passes these sampling parameters.
  • What to do: Search your codebase for 20250514 and swap to claude-sonnet-4-6 or claude-opus-4-8; then search for any code that sets temperature, top_p, or top_k and remove those parameters entirely from requests going to Opus 4.7 or newer — Anthropic's guidance is to steer model behavior through prompting, not sampling params. Do not replace with different values; remove the fields.
  • Why trust it: Anthropic's official API deprecation page and migration guide; the 400-on-sampling-params behavior confirmed independently by multiple Cursor community forum reports of Opus 4.7 failing on AWS Bedrock, and by Apiyi.com's detailed migration write-up.
  • Skeptic check: The 400 only fires on non-default values — if your code sets temperature=1.0 and that happens to be the actual default, it may not trigger; the safest path is to remove the parameters entirely rather than trying to identify the precise default.

Gemini CLI stops working June 18; Antigravity /usage needs a restart to reflect real usage

  • Source: Google Developers Blog (primary); The New Stack; The Register; DEV Community hands-on review
  • Link: Transitioning Gemini CLI to Antigravity CLI — Google Developers Blog
  • TL;DR: In 3 days, Gemini CLI stops serving requests for Google AI Pro, Ultra, and free users. The replacement, Antigravity CLI, uses a weekly compute-based quota instead of a daily request cap, and ships with a known issue: the /usage command only updates after you quit and relaunch, so during a long agent run you cannot see how much quota you have left. Google has acknowledged the lag but has not fixed it yet. Enterprise Gemini Code Assist license holders keep the old CLI indefinitely.
  • What to do: Install Antigravity CLI and complete the migration before June 18 if you're on a non-enterprise plan; don't rely on /usage mid-session — check the Google AI Studio dashboard or use the quota API endpoint instead; factor in that weekly caps and multi-day lockouts have been reported, so stress-test your quota headroom before running long agentic workflows.
  • Why trust it: Google Developers Blog (authoritative shutdown date); The Register and The New Stack reported the migration with independent coverage; the /usage lag is confirmed by multiple user reports on the Google AI Developers Forum and a DEV Community hands-on review of Antigravity 2.0.
  • Skeptic check: Google could fix the /usage lag before or after June 18 — check Antigravity's release notes before building workarounds around it.

Claude Code hook file-path patterns now work (v2.1.176, June 12 — flagged miss from prior run)

  • Source: Anthropic Claude Code changelog (code.claude.com/docs/en/changelog)
  • Link: Claude Code changelog — Anthropic
  • TL;DR: Hook if conditions using file-path glob patterns — Edit(src/**), Read(~/.ssh/**), Read(.env) — were silently broken: the patterns never matched. v2.1.176 (June 12) fixes this. The same release also closed a model-restriction bypass: alias model picks could be redirected to blocked models via ANTHROPIC_DEFAULT_*_MODEL environment variables, ignoring the availableModels allowlist.
  • What to do: Run claude update to get v2.1.176; retest any hook that uses file-path glob patterns in its if condition, as it will now fire where it wasn't before; review your hook allowlists to confirm the newly-working patterns don't open unintended access paths.
  • Why trust it: Anthropic's official Claude Code changelog. This release was flagged as a missed item in the previous digest's Prompt Friction section.
  • Skeptic check: The duration of the file-path pattern bug is not documented in the changelog; hooks using non-path conditions (tool-name matches, negation) were unaffected.

Selective context retrieval scores 10 points higher than full history replay at 8x fewer tokens

  • Source: arXiv:2606.09900 (Liuyin Wang, submitted June 5, 2026); code at github.com/ly-wang19/engram
  • Link: Less Context, More Accuracy: A Bi-Temporal Memory Engine for LLM Agents — arXiv:2606.09900
  • TL;DR: Replaying a growing conversation history into the prompt for every agent turn doesn't just get expensive — it actively hurts accuracy as the session lengthens because outdated or conflicting context confuses the model. Retrieving a targeted 9.6k-token slice (conflict-resolved facts plus relevant session chunks) scored 10 points higher on a 500-question memory benchmark than dumping the full 79k-token history.
  • What to do: If your agent harness stuffs the full session history into context, replace it with a retrieval step: pull the most recent relevant chunks plus any resolved facts for the current task; the open-source Engram library (MIT license) is a working starting point that takes roughly an afternoon to integrate.
  • Why trust it: 500-question LongMemEval_S benchmark; authors publish per-question raw logs and a fully reproducible eval harness in the repo; code is open-source and auditable. Note: paper submitted June 5, just outside the strict 7-day arXiv window; it may have been covered in an earlier digest.
  • Skeptic check: Benchmark uses synthetic personal-assistant Q&A; gains may be smaller for coding-agent sessions where the full file content and tool outputs are all directly task-relevant, not just a source of distractor facts.
