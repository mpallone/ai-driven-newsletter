Cursor's first-party model matches Opus 4.7 at one-tenth the cost

  • Source: Cursor blog
  • Link: Introducing Composer 2.5 — Cursor
  • TL;DR: Cursor's new Composer 2.5, built on Kimi K2.5 with 25× more synthetic training tasks and targeted RL feedback at the exact trajectory points where the model went wrong, scores 79.8% on SWE-Bench Multilingual — matching Opus 4.7 and GPT-5.5 — while costing roughly one-tenth as much at the interactive tier.
  • What to do: If token cost is a bottleneck for high-volume agentic Cursor workflows, switch to Composer 2.5 as your default model and compare real-task completion rates against your current Opus 4.7 baseline before committing.
  • Why trust it: Cursor measured on SWE-Bench Multilingual (community-recognized third-party benchmark) and their own CursorBench v3.1; pricing is published in the release post; competing model scores (Opus 4.7, GPT-5.5) cited for direct comparison.
  • Skeptic check: CursorBench v3.1 is Cursor's own benchmark — the community has not independently verified whether it correlates with real-world completion rates on tasks outside Cursor's training distribution.

Genkit 2.0 ships GA with built-in MCP server integration and Cloud Trace

  • Source: Google Developers Blog / Firebase
  • Link: New AI capabilities for popular frameworks in Firebase Studio — Google Developers Blog
  • TL;DR: Firebase Genkit 2.0 hit general availability at Google I/O 2026 with native Model Context Protocol (MCP) support built in: you can now expose your Genkit tools and prompts as an MCP server, or consume any MCP server's tools as Genkit flows — all with streaming and production observability via Cloud Trace, in one GA TypeScript/JavaScript package.
  • What to do: If you're building MCP servers in TypeScript or JavaScript, evaluate Genkit 2.0 as the scaffold — it bundles flow orchestration, multi-model routing, tool calling, and MCP server/client in a single GA library rather than requiring separate integrations for each.
  • Why trust it: GA announced by Google at the Google I/O 2026 keynote on May 19; Cloud Trace integration confirmed in Firebase release notes; MCP plugin has been available in pre-GA, with GA adding production support commitments.
  • Skeptic check: "Native MCP server integration" has been in Genkit as a separate plugin since before GA — verify whether the GA release adds new capabilities or primarily just locks in the API surface and SLA.

Context-aware prompt injection defeats all existing defenses

  • Source: arXiv 2605.03378 — ARGUS paper
  • Link: ARGUS: Defending LLM Agents Against Context-Aware Prompt Injection — arXiv
  • TL;DR: Attacks that adapt their injected text to match the agent's current task state (what tool just ran, what the user asked, what the agent is about to do) get through every tested defense — because all existing defenses only check for static injection strings, not injections that blend into live context. ARGUS tracks which context pieces influenced each agent decision via a provenance graph, then blocks actions that can't be justified by trustworthy context alone.
  • What to do: When building agents that process untrusted content — web scrapes, MCP tool results, user-supplied documents — label each context item with its provenance (system-authored, user-provided, external tool) and add a verification step that checks whether the agent's next action is justified by system-trusted context before it executes.
  • Why trust it: Authors introduce AgentLure, a benchmark spanning 4 agentic domains and 8 attack vectors; they test it against all publicly available defenses and show categorically higher bypass rates for context-aware attacks; the paper is from May 2026 (arXiv ID 2605.03378).
  • Skeptic check: ARGUS is a research prototype — the provenance graph adds runtime overhead not yet quantified for production systems, and AgentLure is a new benchmark without independent replication.

Best coding model switched providers five times in six months

  • Source: Simon Willison (simonwillison.net) — PyCon US 2026 lightning talk
  • Link: The last six months in LLMs in five minutes — Simon Willison
  • TL;DR: In annotated slides from a PyCon US 2026 lightning talk, Willison documents that the "best coding model" — measured using his reproducible SVG pelican-on-bicycle test run consistently across all major releases — changed hands five times between the three large providers since November 2025, which he identifies as the inflection point when coding capability meaningfully accelerated.
  • What to do: Don't hardcode a single model into your agent harness; use a config-driven or abstraction-layer model selection so you can swap in under an hour when the ranking shifts again — because based on this pattern, it will.
  • Why trust it: Willison has run the same pelican SVG test across every major model release for over a year, providing a consistent cross-model comparison; the count of five provider switches is his qualitative judgment, not a single objective benchmark.
  • Skeptic check: "Best model" is task-dependent — the pelican SVG test reflects creative generation quality, not code correctness; the five-switch count could differ on coding-specific benchmarks like SWE-Bench.
