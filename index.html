Claude Code 2.1.128 fixes worktree branch source and isolates subprocess telemetry

  • Source: Anthropic, Claude Code changelog, May 4, 2026
  • Link: Claude Code releases — GitHub
  • TL;DR: Five changes in 2.1.128 stand out: (1) EnterWorktree now creates branches from local HEAD instead of origin/<default-branch>, so unpushed commits are preserved when you open a worktree; (2) subprocesses — Bash, hooks, MCP servers, LSP — no longer inherit OTEL_* environment variables, fixing accidental trace bleed into Claude Code's own OTLP endpoint from any OTEL-instrumented tool you run via Bash; (3) /mcp now shows a tool count for each connected server, giving you a fast connectivity check without leaving the CLI; (4) --plugin-dir now accepts .zip archives in addition to directories, making plugin distribution easier; (5) the claude_code.skill_activated telemetry event now fires for user-typed slash commands (not just model-invoked ones) and carries a new invocation_trigger attribute ("user-slash", "claude-proactive", or "nested-skill").
  • What to do: Update with npm install -g @anthropic-ai/claude-code; if you rely on worktrees with locally staged but unpushed commits, verify your branching behavior is now correct; if you run OTEL-instrumented services through the Bash tool, remove any manual unset OTEL_* workaround you added.
  • Why trust it: Official Anthropic Claude Code changelog for v2.1.128, released May 4, 2026, cross-referenced against npm registry version history and multiple changelog tracking sources.
  • Skeptic check: OTEL_* inheritance fix and worktree behavior confirmed in search snippets; the full 37-change list was not independently verified, so minor details may differ from the official log.

Cursor Enterprise gets per-provider model blocklists and soft spend limits

  • Source: Cursor, changelog, May 4, 2026
  • Link: Cursor changelog — May 4, 2026
  • TL;DR: Enterprise admins now get granular allow/blocklists at the model and provider level — including blocking entire providers or specific model configurations by speed or context window size, with an option to block new providers by default. Spend limits can now be set as soft limits (alert users at 50%, 80%, and 100% but keep them working) rather than only hard limits (cut access off). Teams with existing blocklists must migrate to the new system by June 1, 2026.
  • What to do: If you admin a Cursor Teams or Enterprise account, migrate existing blocklists to the new model controls before June 1; switch any hard spend limits to soft limits so engineers aren't blocked mid-session.
  • Why trust it: Official Cursor changelog entry for May 4, 2026; no third-party measurement — primary source facts only.
  • Skeptic check: Applies only to Cursor Teams and Enterprise plans; no impact on individual or Pro accounts.
