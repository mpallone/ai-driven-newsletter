Harness iteration beats hand-designed scaffolding

  • Source: arXiv cs.SE, submitted April 28, 2026
  • Link: Agentic Harness Engineering: Observability-Driven Automatic Evolution of Coding-Agent Harnesses (arXiv 2604.25850)
  • TL;DR: A coding agent that observes its own failures and rewrites its scaffolding — the prompts, tool schemas, and retry logic around the model — outperformed a hand-designed harness on a terminal-coding benchmark. The key design move: every harness component is a named file the agent can read, diff, and replace. This makes it possible to trace any failed turn back to the specific component that caused it, whether the iterating is done by an agent or a human.
  • What to do: Break your harness into named, file-backed components — a separate file for the system prompt, one per tool schema, one for retry/fallback policy — rather than keeping everything inline in code; even without any auto-evolution system, this structure makes it straightforward to spot which component is responsible for a failure and change just that piece.
  • Why trust it: The AHE system ran for 10 full iterations on the open-source Terminal-Bench 2, lifting pass@1 from 69.7% to 77.0%; it beat the hand-designed Codex-CLI harness (71.9%) and two self-evolving baselines (ACE and TF-GRPO); code is published alongside the paper.
  • Skeptic check: Terminal-Bench 2 tests terminal and coding tasks; the gains from file-level component separation may not transfer to harnesses that depend on stateful browser interactions, long-running multi-agent coordination, or highly domain-specific tool schemas.
