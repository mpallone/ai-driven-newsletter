Anthropic data: sandbox beats classifier for agent safety

  • Source: Anthropic — engineering blog, ~May 30, 2026
  • Link: How we contain Claude across products — anthropic.com
  • TL;DR: Anthropic's internal telemetry shows users approved ~93% of permission prompts — approval fatigue is real and prompts alone don't hold up as agents run longer. Adding a sandbox (filesystem + network isolation) cut those prompts by 84%. The auto mode classifier that gates command approval has a 0.4% false-positive rate on benign commands but still lets ~17% of risky actions through — so it is one defense layer inside a sandbox, not a replacement for one. Three CVEs were disclosed against Claude Code (mid-2025 through January 2026), all exploiting code that runs before user consent. A February 2026 internal red-team exercise showed an employee being phished into launching Claude Code with a malicious prompt.
  • What to do: Add filesystem and network isolation as your primary containment layer before enabling auto mode or reducing permission prompts; treat the classifier as defense-in-depth inside the sandbox, not as your perimeter.
  • Why trust it: Anthropic internal production telemetry; three named CVEs with specific date ranges; a controlled red-team exercise described with specifics (February 2026); named sandbox technologies in production across three products: gVisor for claude.ai, Seatbelt on macOS + Bubblewrap on Linux for Claude Code, Apple Virtualization framework / HCS for Cowork.
  • Skeptic check: The 84% reduction in permission prompts from sandboxing likely reflects that most prompts covered routine low-risk file access; the remaining ~16% of higher-risk calls still require review — and the 17% classifier pass-through rate means some of those still slip through auto mode.
