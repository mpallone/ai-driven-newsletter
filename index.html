Fixing the harness beats upgrading the model for agent failures

  • Source: arXiv cs.AI / cs.SE — Tianshi Xu, Huifeng Wen, Meng Li (submitted May 21, 2026)
  • Link: Adapting the Interface, Not the Model: Runtime Harness Adaptation for Deterministic LLM Agents — arxiv.org
  • TL;DR: Most repeated agent failures in structured task environments come from harness interface problems — mismatches in how tool outputs are formatted, how actions are described, how errors are fed back to the model — not from the model's underlying capability. The researchers patched only the harness layer (keeping model weights and benchmark environments frozen) and fixed the majority of failure cases across 7 benchmark environments and 18 model backends.
  • What to do: When an agent repeatedly fails on a specific task, audit tool output formatting, action representation, and error feedback first — before concluding the model needs to be upgraded or swapped.
  • Why trust it: Tested across 7 deterministic agent benchmarks and 18 model backbones; model weights and benchmark environments were held constant throughout; only the harness interface changed; 116 of 126 model-environment settings improved, with an 88.5% average relative improvement.
  • Skeptic check: All benchmarks are deterministic, rule-governed environments (game-like or structured task settings); production harnesses dealing with messier real-world inputs and open-ended tasks may show different failure distributions, and the 90% interface-failure figure may not transfer directly.
