Dynamic workflows: three orchestration patterns Claude uses when you say "ultracode"

  • Source: Anthropic — claude.com blog (June 2, 2026)
  • Link: A harness for every task: dynamic workflows in Claude Code
  • TL;DR: When you include the keyword ultracode in a prompt (or run /effort ultracode for the whole session), Claude Code writes a JavaScript orchestration script on the fly, fans work out to parallel subagents, and synthesizes results — saving the script so you can inspect or rerun it. The June 2 blog documents three reusable patterns: a classifier router that assigns subtasks to specialist subagents based on type, a validator chain where one subagent checks another's output before it reaches you, and a sequential decomposer that breaks a large task into chunks with one agent per chunk. Within a workflow, Claude also selects which model each subagent uses and whether it gets its own isolated worktree — so you can mix fast cheap agents for drafts with a more capable agent for final review.
  • What to do: Add ultracode to prompts for large codebase tasks (audits, migrations, cross-file refactors); after each run, open the saved orchestration script to understand what Claude actually did before you re-run it on a wider scope.
  • Why trust it: Primary Anthropic blog post (June 2, 2026) describing an in-production feature; feature is in research preview backed by official docs at code.claude.com/docs/en/workflows. The May 28 launch post documented the feature exists; this June 2 post provides the implementation patterns.
  • Skeptic check: Research preview, not GA; token consumption can be substantially higher than a single-agent session; only available on Max, Team, and Enterprise plans — Free and Pro users cannot use dynamic workflows.

v2.1.161 patches OAuth leak in custom gateways and MCP policy bypass in subagents

  • Source: Anthropic — Claude Code changelog, v2.1.161 (June 2, 2026)
  • Link: Claude Code release notes — claudeupdates.dev
  • TL;DR: Three fixes worth acting on: (1) custom API gateways were receiving the user's Anthropic OAuth credential instead of the gateway's own token, potentially exposing user credentials to the gateway operator — this was a regression; (2) subagents launched via the Agent tool were silently ignoring --strict-mcp-config, --bare, remote-mode restrictions, and enterprise managed MCP server allow/deny policies, meaning MCP tools you had blocked could be called by subagents without your knowledge; (3) OTEL_RESOURCE_ATTRIBUTES values are now forwarded as labels on metric datapoints, letting you slice usage and cost by team or repo in any OpenTelemetry backend. A fourth fix: a failed Bash call in a parallel batch no longer cancels the other calls in the same batch, so partial failures in parallel tool use are now isolated.
  • What to do: Update to v2.1.161 now if you use a custom API gateway or if you have set MCP security policies (--strict-mcp-config or enterprise MCP allow/deny); add OTEL_RESOURCE_ATTRIBUTES=team=yourteam,repo=yourrepo to your environment to get per-team and per-repo cost breakdowns in your telemetry stack.
  • Why trust it: Official Anthropic release v2.1.161 (June 2, 2026); version confirmed via npmjs.com/@anthropic-ai/claude-code timestamp and corroborated by claudeupdates.dev and releasebot.io citing the same changes. 22 total changes in the release; only the four above met the practitioner-relevance bar.
  • Skeptic check: The OAuth credential leak only affected custom API gateway setups — if you connect directly to Anthropic (no gateway proxy), fix (1) does not apply to you. The MCP policy bypass affects anyone who assumes subagents inherit parent-session MCP restrictions; if you don't set MCP deny policies, fix (2) has no operational impact for you today.
