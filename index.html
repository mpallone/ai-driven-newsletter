Hooks for hyphenated agent names were silently mismatching until v2.1.195

  • Source: Anthropic — Claude Code release notes
  • Link: Claude Code v2.1.195 release notes — GitHub, June 26, 2026
  • TL;DR: If you had hooks or auto-mode deny rules referencing hyphenated names — code-reviewer, mcp__brave-search, any mcp__server-name__tool — they were doing substring matching, not exact matching. So a rule for mcp__brave-search would match mcp__brave-search__web_search and also any other tool whose name happened to contain that substring. Fixed in v2.1.195 to exact-match only. To intentionally match all tools from a hyphenated MCP server going forward, use the pattern mcp__brave-search__.*.
  • What to do: Audit every hook matcher and auto-mode deny pattern in your .claude/settings.json that contains a hyphen — test that they still fire after upgrading, and update any that relied on the old substring behavior by appending __.* where you want wildcard matching.
  • Why trust it: First-party Claude Code release notes, June 26, 2026; exact-match vs. substring behavior is verifiable by adding a test hook against a hyphenated MCP server name.
  • Skeptic check: The fix only affects new evaluations; existing sessions started before upgrading will not retroactively reapply rules.

Claude Code now logs assistant response text to OpenTelemetry

  • Source: Anthropic — Claude Code release notes
  • Link: Claude Code v2.1.193 release notes — GitHub, June 25, 2026
  • TL;DR: A new claude_code.assistant_response OpenTelemetry log event now emits what the model said during a session. Disabled by default to avoid accidentally leaking sensitive context; set OTEL_LOG_ASSISTANT_RESPONSES=1 to turn it on. Combined with the existing tool-call events, this gives you full trace coverage of a Claude Code session in your OTel collector.
  • What to do: Add OTEL_LOG_ASSISTANT_RESPONSES=1 to your monitoring environment variables if you already have an OTel pipeline for Claude Code — you can now correlate assistant reasoning text with tool calls and outcomes in the same trace.
  • Why trust it: First-party Claude Code release notes, June 25, 2026; behavior is verifiable by enabling the flag and inspecting OTel output.
  • Skeptic check: Enabling this will pipe full model responses — including any sensitive content from your prompts — to your OTel backend; verify your collector's data handling before turning it on in production.

Background agents no longer stop the main session when launched

  • Source: Anthropic — Claude Code release notes
  • Link: Claude Code v2.1.193 release notes — GitHub, June 25, 2026
  • TL;DR: When Claude Code launched a background agent, an injected instruction told the main agent to "end your response" — which caused it to stop working on other concurrent tasks. That instruction is removed in v2.1.193. The fix also stops pinned background agents from asking "Continue from where you left off?" after every auto-update, and fixes a bug where backgrounding a main turn spawned a phantom "general-purpose (resumed)" subagent.
  • What to do: If you have harnesses that rely on the main agent pausing after spawning a background agent, verify your control flow still works as expected after upgrading — the main agent will now continue rather than stop.
  • Why trust it: First-party Claude Code release notes, June 25, 2026; reproducible by starting a background agent and observing main-session behavior before and after upgrade.
  • Skeptic check: Harnesses that depend on the old pause-after-launch behavior will need to add an explicit stop or wait mechanism.

New setting routes all shell commands through auto-mode classifier

  • Source: Anthropic — Claude Code release notes
  • Link: Claude Code v2.1.193 release notes — GitHub, June 25, 2026
  • TL;DR: By default, auto-mode only sends shell commands that look like arbitrary code execution through the classifier. Setting autoMode.classifyAllShell: true in your Claude Code config sends every Bash and PowerShell command through it, giving you finer-grained allow/deny control in automated pipelines. The same release also adds denial reasons to the transcript and to the /permissions panel so you can see exactly why a command was blocked.
  • What to do: If you run Claude Code in auto-mode pipelines and want tighter shell controls, add "autoMode": {"classifyAllShell": true} to your .claude/settings.json, then check the denial log under /permissions to tune your allow list.
  • Why trust it: First-party Claude Code release notes, June 25, 2026; behavior is testable by running a benign command and checking whether it appears in the classifier log.
  • Skeptic check: Running all commands through the classifier adds latency; measure the impact on pipeline throughput before enabling in time-sensitive automation.

/rewind now restores conversation context after /clear

  • Source: Anthropic — Claude Code release notes (v2.1.185–v2.1.193)
  • Link: Claude Code releases — GitHub
  • TL;DR: Previously, running /clear to wipe a conversation was permanent — /rewind could not recover it. The June 22–26 releases extend the checkpoint system so /rewind can go back to a state before /clear was run, restoring prior conversation and file state. This applies to both the checkpoint-menu UI (Esc twice) and the /rewind command.
  • What to do: If you habitually run /clear to reset context and then regret losing the thread, you no longer need to; use /rewind to recover. For automated sessions, note that checkpoints now persist across clears, which increases disk use over long sessions.
  • Why trust it: Multiple third-party writeups (explainx.ai, mindstudio.ai) corroborate the feature alongside Claude Code's own docs update; testable by running /clear then /rewind in any recent Claude Code session.
  • Skeptic check: Checkpoint storage is local; on shared or ephemeral machines the checkpoint files may not persist, limiting recovery options.

Claude Code turns any JSON data repo into a CORS-open SQLite MCP resource

  • Source: Simon Willison's Weblog
  • Link: browser-compat-db — simonwillison.net, June 24, 2026
  • TL;DR: Willison used Claude Code (Opus 4.8, web session) to write a sqlite-utils script that converts Mozilla's mdn/browser-compat-data JSON repository into a ~66 MB SQLite database. A GitHub Actions workflow rebuilds the database on each upstream commit and force-pushes it to an orphan branch, making it available via GitHub's CDN with open CORS headers. The result is queryable directly from Datasette Lite in a browser tab, and usable as an MCP resource — no backend needed.
  • What to do: Use this pattern for any JSON data repository you want to query: ask Claude Code to write the sqlite-utils conversion script, add a GitHub Actions workflow that commits the .db to an orphan branch, and point Datasette Lite or your MCP server at the GitHub CDN URL with open CORS headers set on the branch.
  • Why trust it: Working database published at the GitHub repo; Claude Code web transcript available; the pattern reuses existing open-source tooling (sqlite-utils, Datasette Lite) with no novel infrastructure.
  • Skeptic check: The orphan-branch force-push pattern works for read-only public data; it's not suitable for large binary files or frequently updated datasets where GitHub CDN caching creates stale-data windows.

Claude Tag introduces ambient-monitoring shared agent pattern inside Slack

  • Source: Anthropic
  • Link: Introducing Claude Tag — Anthropic, June 23, 2026
  • TL;DR: Claude Tag runs as one shared agent identity inside a Slack channel — any team member can delegate tasks by typing @Claude, and the agent accumulates context across conversations over time. In "ambient mode" (admin-enabled), the agent monitors channels without being tagged: it proactively surfaces relevant information, follows up on threads that went quiet without resolution, and flags developments from channels it has access to. It runs on Opus 4.8 and is available in beta on Enterprise and Team plans.
  • What to do: Watch this; no action yet for most practitioners — the ambient monitoring and shared-context agent design patterns (one agent identity, persistent channel memory, proactive surfacing without being invoked) are directly relevant to agent harness architecture, but the implementation is currently only accessible through Anthropic's hosted product, not as a harness you can configure yourself.
  • Why trust it: Anthropic first-party announcement with concrete feature descriptions; Anthropic reports internally that 65% of their product team's code is created by their internal version of Claude Tag, though this is self-reported and unaudited.
  • Skeptic check: Ambient mode relies on the agent having broad channel read access, which raises both privacy and prompt-injection risks — an attacker controlling messages in a monitored channel could influence what the agent proactively surfaces to the team.
