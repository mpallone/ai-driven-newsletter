Claude Code & Anthropic platform

Two Claude Code point releases landed in the window, plus a security wrinkle on a feature that just went GA, plus new cost controls for Enterprise admins.

Claude Code subagents run in background by default

  • Source: Anthropic — Claude Code CHANGELOG.md
  • Link: Claude Code CHANGELOG — v2.1.198, GitHub
  • TL;DR: As of v2.1.198 (July 1), subagents you launch now keep running in the background while your main session keeps working, instead of blocking it, and they can auto-commit, push, and open a draft PR when they finish a coding task. The same release put the built-in Explore agent on the main session's model (capped at Opus) instead of Haiku, added a /dataviz skill, and removed the interactive /agents wizard in favor of editing .claude/agents/ files directly.
  • What to do: If you have automation or hooks that assumed subagents block the main thread until done, re-check them against the new background-by-default behavior, and if you were relying on the /agents wizard, switch to editing agent files directly.
  • Why trust it: Pulled directly from Anthropic's own CHANGELOG.md on GitHub, fetched via raw.githubusercontent.com, with a dated v2.1.198 entry for July 1, 2026.

  • Link: Claude Code CHANGELOG — v2.1.199, GitHub

Claude in Chrome reaches general availability

  • Source: Anthropic — Claude Code CHANGELOG.md; security context from Koi Security
  • Link: Claude Code CHANGELOG — v2.1.198, GitHub
  • TL;DR: Claude in Chrome — letting Claude Code drive the browser for testing, console debugging, form automation, and page-data extraction — went GA in v2.1.198 (July 1). A browser-extension flaw disclosed earlier this year by security researchers at Koi Security showed that an unprivileged browser extension could inject hidden instructions that hijacked the Claude Chrome extension's actions; Anthropic has said Opus 4.5 cuts prompt-injection success to about 1% in its internal testing.
  • What to do: Before turning on Claude in Chrome for real work, audit which other browser extensions run in the same profile, since the attack surface is other extensions injecting content the agent then treats as trusted.
  • Why trust it: The GA date comes directly from Anthropic's CHANGELOG.md; the injection research is a named security firm's public disclosure and Anthropic's own reported mitigation number, not independently reproduced by us.
  • Skeptic check: The 1% figure is Anthropic's internal test result, not a third-party audit, and the original vulnerability disclosure predates this GA launch — it's unclear whether the underlying extension-injection class of attack has been fully closed or just made less likely.

Google automates agent eval with agents-cli

  • Source: Google Developers Blog
  • Link: Driving the Agent Quality Flywheel from Your Coding Agent — Google Developers Blog, ~July 1, 2026
  • TL;DR: A new agents-cli eval command chains five steps: an LLM generates realistic multi-turn test conversations straight from your agent's own instructions and tool definitions (no hand-written test cases), runs your agent against them, grades the resulting traces with the same "AutoRater" scoring approach Google uses to evaluate its own models, clusters the failure modes, and then automatically rewrites your system instructions against the test suite using the GEPA optimization algorithm.
  • What to do: If you're maintaining eval test cases by hand for a coding or support agent, try generating them from your agent's own instructions/tools instead — it removes a maintenance burden that usually causes eval suites to go stale.
  • Why trust it: This is a named, concrete CLI tool with named commands and a named optimization algorithm (GEPA) from Google's own developer blog; we could not load the page directly and relied on indexed search summaries, and no published benchmark numbers were found for how much the auto-generated tests improve over hand-written ones.
  • Skeptic check: No head-to-head comparison against hand-written eval suites was found — the claim that auto-generated scenarios are "diverse" and catch real failure modes is Google's framing, not an independently measured result.

Practitioner findings

Three items with real evidence behind them, not just announcements.

Vague system-prompt wording causes agent retry loops

  • Source: Simon Willison
  • Link: Using DSPy to evaluate and improve Datasette Agent's SQL system prompts — Simon Willison, July 2, 2026
  • TL;DR: Willison built a harness where DSPy agents call his Datasette Agent's real tools and prompts against a live database, and traced a concrete failure: the schema listing only gave table names (no columns), while the system prompt separately said "don't call describe_table if you already have the information" — the combination made small models guess column names and fall into error-retry loops.
  • What to do: If your system prompt tells the model to skip a lookup tool "when you already have the information," check that the information you actually gave it is complete enough to make that true, or soften the instruction.
  • Why trust it: One practitioner's own dogfooding case study on his real production tool, tested against GPT-4.1 mini/nano, with an auto-generated gold-standard eval dataset and custom metrics — not a large-scale controlled study, but a concrete, reproducible failure trace on a real system.
  • Skeptic check: This is a single project's traces with a couple of specific small models, not a broad multi-model benchmark — the general lesson (ambiguous "skip if you already know X" instructions are risky) is more trustworthy than the specific schema-listing fix.

A skill can encode 45 design rules

  • Source: Latent Space (interview with Paul Bakaus)
  • Link: Skill engineering and the case against one-shot AI design — Latent Space, ~July 2, 2026
  • TL;DR: Paul Bakaus built Impeccable, an open-source design skill for coding agents that packages 23 commands and 45 deterministic detector rules that give an agent operationally precise definitions for vague design terms like "bolder" or "denser," so it fixes one section at a time with a human checking each step instead of regenerating the whole page in one shot.
  • What to do: When a skill's instructions rely on subjective adjectives, replace them with a checklist of deterministic, checkable rules the way Impeccable does for design language — inspect its rule set on GitHub as a template.
  • Why trust it: The claims are checkable against a real open-source repository (45 detector rules, 23 commands) rather than just an interview description; no adoption or accuracy numbers were given for how well the detectors work in practice.
  • Skeptic check: This is one open-source project from its creator's own account in an interview, not an independent audit of whether the 45 rules actually reduce bad output versus a baseline.

Long-context models skip evidence already in view

  • Source: arXiv (Zhao et al., UIUC)
  • Link: ReContext: Recursive Evidence Replay as LLM Harness for Long-Context Reasoning — arXiv, July 2, 2026
  • TL;DR: Even when the right evidence is already sitting inside a long context window, models often don't use it — the paper's fix has the model find and re-quote the relevant spans itself, then "replays" just that evidence back to it right before the final answer, without discarding the rest of the context.
  • What to do: For long-context tasks where the model seems to ignore relevant material you already gave it, try explicitly re-surfacing the key evidence near the end of your prompt right before asking for the final answer, rather than trusting the model to find it unprompted.
  • Why trust it: Tested across 8 long-context datasets at 128K tokens on three different open model backbones (Qwen3-4B, Qwen3-8B, Llama3-8B), with the technique ranking best on average across all three against baseline approaches; code was released alongside the paper.
  • Skeptic check: Tested only on smaller open models (4B–8B), not on the frontier models most practitioners actually use for coding agents, so the size of the benefit on a model like Sonnet 5 or GPT-5.6 is unverified.
