Anthropic maps all 7 ways to control Claude Code behavior

  • Source: Anthropic Claude blog (June 18, 2026)
  • Link: Steering Claude Code: skills, hooks, subagents and more — Anthropic
  • TL;DR: Anthropic published an official guide to the seven mechanisms for controlling Claude Code behavior: CLAUDE.md (project-level context, always loaded into the session); rules (targeted constraints at project or user scope); skills (procedural instructions loaded only when invoked via slash command, not on every session start); subagents (.claude/agents/ YAML files with their own system prompts, model selection, and tool scopes); hooks (shell commands triggered by events like session start, tool use, or prompt submit); output styles (formatting preferences); and system prompt append (for API or remote-control use). The post includes a decision table for when each mechanism applies.
  • What to do: Audit your current setup against this taxonomy — if you have verbose procedures in CLAUDE.md that are only needed occasionally (deploy steps, migration checklists, release workflows), move them to skills so they are loaded only when invoked and do not consume context tokens on every session start.
  • Why trust it: Primary source from Anthropic's official Claude blog, June 18 2026; describes behavior of shipping product features in Claude Code, not experimental capabilities.
  • Skeptic check: The post describes the available mechanisms but does not benchmark context cost or task success rates across them; which approach is best for a given instruction depends on your project's testing.

Cursor /automate builds persistent trigger-based agents from plain English

  • Source: Cursor official changelog (June 18, 2026)
  • Link: Cursor changelog — June 18, 2026
  • TL;DR: Cursor 3.8's new /automate command creates a persistent automation from a plain-English description inside your current agent session — Cursor infers the triggers, tool set, and instructions for you. New triggers added in this release: react to any Slack message with a designated emoji to kick off a cloud agent; or fire on GitHub issue comments or PR review comments (inline diff comments on a pull request). Cloud agents started by automations now have computer use enabled by default: after writing code, the agent can start the app, click through it, and record screenshots and video, which are then attached as artifacts to the PR so reviewers see what the agent actually tested.
  • What to do: Convert your most frequent repetitive agent invocations into persistent automations with /automate — prime candidates are auto-fixing PR review comments on emoji reaction, triaging failed GitHub Actions, and generating release notes on merge; the computer use artifacts make automation output auditable by reviewers without manual re-testing.
  • Why trust it: Cursor official changelog at cursor.com/changelog/06-18-26, June 18 2026; consistent with their previously announced cloud agents architecture.
  • Skeptic check: Computer use is on by default for every automation and adds compute cost per run; measure per-run cost on a low-frequency trigger before deploying at scale.

Claude Code auto mode now blocks destructive git and infrastructure commands

  • Source: Anthropic Claude Code changelog, version 2.1.183 (June 19, 2026)
  • Link: Claude Code changelog — Anthropic
  • TL;DR: In auto mode, Claude Code 2.1.183 refuses to run git reset --hard, git checkout -- ., git clean -fd, and git stash drop unless you explicitly asked to discard local work in the same conversation. git commit --amend is blocked if the commit being amended was not created by the agent this session. terraform destroy, pulumi destroy, and cdk destroy are blocked unless you named that specific stack in your request. Separately, model deprecation warnings now surface when a deprecated model is specified in agent YAML frontmatter (not only in CLI flags or via /model), and a new attribution.sessionUrl setting lets you omit the claude.ai session deep-link that Claude Code otherwise appends to commit messages and PR descriptions.
  • What to do: Update to 2.1.183 with claude update, especially if you run auto mode on git-heavy or infrastructure workflows — you get meaningful protection against accidental data loss with no config changes required. If any subagent frontmatter or agent config pins a specific model version string, verify each one against the current deprecation list now to avoid silent upgrades.
  • Why trust it: Anthropic Claude Code official changelog, version 2.1.183, June 19 2026.
  • Skeptic check: The destructive command blocking applies only in auto mode; --dangerously-skip-permissions bypasses all of these guards.

New open spec lets agents discover your MCP servers via ai-catalog.json

  • Source: AgenticResourceDiscovery.org spec; Hugging Face blog (June 17–18, 2026)
  • Link: Agentic Resource Discovery specification — agenticresourcediscovery.org
  • TL;DR: The ARD (Agentic Resource Discovery) draft specification defines how AI agents find available tools without a hardcoded registry. Publishers host a static manifest at /.well-known/ai-catalog.json listing their skills, MCP servers, and ML applications. Agents or harnesses query this endpoint at discovery time to find what is available. The spec launched with backing from Google, GitHub, and Microsoft, and Hugging Face released a reference client/server (hf-discover) that indexes thousands of Hugging Face Spaces as discoverable skills and MCP servers.
  • What to do: Watch this; no action yet — the spec is a draft and the schema may change. If you host MCP servers or agent skills publicly, bookmark agenticresourcediscovery.org and plan to add /.well-known/ai-catalog.json once the spec stabilizes; it may become how harnesses auto-discover tools without explicit configuration.
  • Why trust it: Specification published at agenticresourcediscovery.org; Hugging Face blog confirms the reference implementation; developer-tech.com confirmed Google and GitHub backing as of June 17, 2026.
  • Skeptic check: Draft status means the schema is not locked — implementing against the current version now risks breaking changes before the spec stabilizes.
