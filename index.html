Ask Claude Code for self-contained HTML, not Markdown, on deliverables

  • Source: Simon Willison (linking to Thariq Shihipar, Anthropic Claude Code team), May 8, 2026
  • Link: Using Claude Code: The Unreasonable Effectiveness of HTML — simonwillison.net
  • TL;DR: When the output is meant to be read by a human — a plan, comparison, code review, explainer, or status report — asking Claude Code to produce a self-contained .html file yields something you'll actually open and navigate rather than a wall of Markdown you'll skim. Thariq Shihipar (Anthropic) illustrated this with 20 concrete example files; each trades a flat text document for one with layout, colour, and navigation. The explicit carve-out is short conversational replies, code-only outputs, and terminal-style answers.
  • What to do: Add "produce a self-contained HTML file" to your prompts or system prompt for report-style, comparison, and review tasks — leave it off for code-only outputs and conversational exchanges.
  • Why trust it: Written by Thariq Shihipar, Anthropic engineer on the Claude Code team; 20 concrete example .html files published; HN thread (id 48071940) opened within hours of publication. Single author, no controls.
  • Skeptic check: Practitioner recommendation backed by examples, not a controlled study — the claim that HTML is "more useful" is not independently measured.

Cursor Bugbot now learns from PR feedback to cut false positives over time

  • Source: Cursor blog, May 8, 2026
  • Link: Bugbot now self-improves with learned rules — Cursor blog
  • TL;DR: Bugbot turns developer reactions (thumbs up/down) and human reviewer comments on pull requests into persistent rules that shape all future reviews in that repo. Teams and Enterprise plans can now also give Bugbot access to MCP servers for additional context (issue tracker, docs, etc.) through the Bugbot dashboard. Since the beta opened, 110,000+ repos enabled learning and 44,000+ rules were auto-generated; the stated resolution rate is now ~80%, which Cursor claims is 15 percentage points above the next closest AI code-review product.
  • What to do: Enable Bugbot learning and consistently react to its comments — thumbs up on a good catch, thumbs down on a false positive; both feed the rule engine directly. On Teams/Enterprise, connect your issue-tracker or docs MCP server from the Bugbot dashboard.
  • Why trust it: Official Cursor blog post; concrete aggregate numbers (110k repos, 44k rules); resolution rate compared to a named competitor class. Cursor's own benchmark, no independent replication.
  • Skeptic check: "Resolution rate" counts bugs fixed before merge; 20% unresolved could be false positives or intentional decisions to fix later — the denominator matters for interpreting the 80% claim.

Rewording your LLM eval criteria flips up to 9% of verdicts on clear-cut cases

  • Source: Weng, Feng, Xie — arXiv:2605.06161, appeared May 8, 2026
  • Link: Beyond Accuracy: Policy Invariance as a Reliability Test for LLM Safety Judges — arXiv
  • TL;DR: Using an LLM to score your agent's outputs is now standard practice, but rewording the evaluation criteria while keeping the meaning the same flips up to 9.1% of verdicts above baseline noise. More troubling: 18–43% of those flips land on cases where the answer should be obvious. The eval score your pipeline reports is less stable than it looks.
  • What to do: Before trusting an LLM judge pipeline, run the evaluation criteria through 3–5 semantically equivalent rewrites and measure what fraction of verdicts change; if you see more than ~5% flips on unambiguous cases, treat your scores as directional only.
  • Why trust it: Submitted May 7, 2026 (appeared May 8); systematic content-preserving rewrites tested against baseline jitter; flip rates broken down by case ambiguity; three falsifiable criteria formalized.
  • Skeptic check: Tests focus on safety-style evaluation tasks; verdict stability for code-quality or helpfulness judges may differ — the finding does not yet generalize beyond safety scoring.

Coding agents lose ~30 accuracy points when all production constraints stack at once

  • Source: Dente, Satriani, Papotti — arXiv:2605.06445, appeared May 8, 2026
  • Link: Constraint Decay: The Fragility of LLM Agents in Backend Code Generation — arXiv
  • TL;DR: Coding agents that pass tests on simple specs fail significantly once you add database schemas, ORMs, architectural patterns, and framework conventions all at once. Assertion pass rates drop ~30 points on average from unconstrained to fully constrained tasks. Minimal, explicit frameworks (Flask) outperform convention-heavy ones (FastAPI, Django) by a substantial margin — the gap is driven by data-layer defects (wrong query composition, ORM runtime violations) that agents generate when they must infer conventions rather than follow explicit specs.
  • What to do: Test your coding agent against the full constraint set it will face in production, not simplified stand-ins; when an agent bootstraps new backend code, bias toward explicit minimal frameworks before layering in convention-heavy dependencies.
  • Why trust it: 80 greenfield + 20 feature-implementation tasks across 8 web frameworks; quantitative assertion pass-rate measurement; submitted May 7, appeared May 8, 2026.
  • Skeptic check: Backend web API generation tasks only — the ~30-point drop and framework rankings may not hold for frontend, data pipelines, or infrastructure work.

Claude Code: failing read-only shell calls no longer cancel their parallel siblings

  • Source: Anthropic, Claude Code CHANGELOG, ~May 8–9, 2026
  • Link: Claude Code releases — GitHub
  • TL;DR: A bug caused a failing read-only shell call (grep, git diff, ls) to cancel every other parallel tool call in the same batch. That is now fixed: each call runs to completion independently. A separate fix in the same release batch stops 1M-context model sessions from throwing a false "Prompt is too long" error before the session actually reaches the API limit — the autocompact window calculation was wrong on large-context models.
  • What to do: Update Claude Code; if you added || true or similar hacks to read-only shell commands to prevent them from killing sibling parallel calls, remove those workarounds.
  • Why trust it: Official Anthropic CHANGELOG; fix described in search snippets as released within the last 1–2 days. Exact version number not confirmed from available sources — verify with claude --version after updating.
  • Skeptic check: Release date is approximate; the fix may already be in whatever version you have installed.
