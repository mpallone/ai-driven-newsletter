Claude Code v2.1.145 patches bash permission bypass

  • Source: Anthropic / Claude Code official changelog
  • Link: Claude Code Changelog — code.claude.com
  • TL;DR: v2.1.145 (May 19) fixes a hole where bare variable assignments (VAR=value without export) in bash commands would skip the permission-prompt check even when that environment variable wasn't on your allowlist. The same release ships claude agents --json for scripting session state into tmux layouts or status bars, adds agent_id and parent_agent_id fields on OpenTelemetry spans for proper multi-agent trace parenting, shows a plugin's component inventory and estimated per-session token cost before you install it, and feeds background_tasks and session_crons into Stop and SubagentStop hook inputs. Also in the same day: v2.1.144 makes /model session-local (press d to change the new-session default), shows background sessions in /resume with a bg marker, and fixes a 75-second startup hang when api.anthropic.com is unreachable.
  • What to do: Update Claude Code immediately; if you run agents with restricted env-variable allowlists, audit recent sessions for unexpected variable mutations via bare assignment.
  • Why trust it: Anthropic's official changelog at code.claude.com/docs/en/changelog; release dated May 19, 2026; the vulnerability and fix are described in the exact patch notes with PR-level detail.
  • Skeptic check: The changelog doesn't detail which workflows were actually reachable through this bypass, so the real-world risk before patching is unknown.

Cursor cloud agents now trigger from Jira tickets

  • Source: Cursor changelog
  • Link: Cursor in Jira — cursor.com changelog, May 19
  • TL;DR: As of May 19, you can assign any Jira work item to Cursor or @Cursor in a comment; a cloud agent picks up the ticket title, description, comments, and your team's repo settings, works through the task, then posts a link to the resulting pull request back in Jira. Requires Jira Commercial Cloud with Atlassian Rovo enabled.
  • What to do: If your team runs Jira Commercial Cloud with Rovo, install the integration from Cursor's integrations page and pilot it on low-risk bug tickets before using it for feature work.
  • Why trust it: Official Cursor changelog entry dated May 19, 2026 with the Rovo requirement stated explicitly; the PR-back-to-Jira completion flow is described as the standard behavior.
  • Skeptic check: Rovo is a paid Atlassian add-on; the integration has no community track record yet, so failure modes (e.g., misread ticket scope, wrong repo) aren't documented.

Codex adds structured JSON output for resumed sessions

  • Source: OpenAI / Codex GitHub releases
  • Link: Codex releases — github.com/openai/codex
  • TL;DR: Codex 0.132.0 (May 20) adds --output-schema to codex exec resume, letting you pass a JSON Schema and receive typed structured output from any resumed session — useful for feeding agent results into downstream pipelines. It also fixes a bug where /goal continuations would loop past usage limits instead of stopping, and unifies the Python SDK with first-class API key, ChatGPT browser, and device-code authentication flows.
  • What to do: Add --output-schema to any codex exec resume calls in automated pipelines where you need typed output; update to 0.132.0 to get the /goal loop-stop fix if you use persistent goal workflows.
  • Why trust it: Official GitHub release notes for release 0.132.0, dated May 20, 2026 from the openai/codex repo; specific flags and bug descriptions are listed with PR numbers.
  • Skeptic check: Output schema adherence depends on model compliance; no accuracy measurements are included in the release notes.

On-demand skill loading shrank system prompt 45%

  • Source: Glean engineering blog
  • Link: The harness as the context manager — Glean blog
  • TL;DR: Glean's v3 agent harness replaced the common pattern of front-loading all tool schemas and instructions at session start (often 20K+ tokens) with search-first skill discovery: skills live in an indexed library and load only when they match the current task. This reduced their system prompt by 45%. The harness also replaces declarative tool schemas with code executed in sandboxes, isolates parallel subtasks in separate subagent context windows, and uses compaction to move raw outputs to the filesystem while keeping only load-bearing task state in context.
  • What to do: Audit your agent system prompt for instruction blocks that only apply to certain tasks; move them into indexed skills that retrieve on demand rather than injecting everything upfront every session.
  • Why trust it: Glean's own production enterprise-search and agent platform; 45% reduction figure published in the engineering post and corroborated by Glean's engineering team on LinkedIn; this is a single company's measurement of their own system with no external controls.
  • Skeptic check: Glean's enterprise search infrastructure makes indexed skill retrieval cheap for them; teams without a similar retrieval layer may find the overhead of building it outweighs the context savings.

Data-instruction separation can't block injection in principle

  • Source: arXiv 2605.17634 — Abdelnabi & Bagdasarian
  • Link: AI Agents May Always Fall for Prompt Injections — arXiv 2605.17634
  • TL;DR: The standard prompt-injection defense — tagging text as "data" vs. "instruction" and only obeying the latter — fails against attacks that blend the injection into context that looks like normal agent activity. This paper shows that any defense tight enough to block a suspicious context flow will also block legitimate flows that look similar, making perfect defense impossible: an attacker can always craft a context under which the injected instruction appears legitimate, and any tighter norms the defender adds will flag some real tasks as attacks.
  • What to do: Treat prompt injection as an unavoidable residual risk rather than a problem you can fully solve; limit agent permissions to reduce blast radius, and require human approval before high-stakes irreversible actions even when injection detection looks clean.
  • Why trust it: Formal analysis backed by adversarial test scenarios; Sahar Abdelnabi has a record of prior prompt-injection attack research; submitted to arXiv May 17, 2026.
  • Skeptic check: The impossibility result holds within the specific contextual integrity framework they use; practical defenses can still reduce attack success rates substantially even if they can't reach zero.

Deeper agent iterations beat many shallow attempts

  • Source: arXiv 2605.15221 — Ishibashi, Yano, Oyamada
  • Link: Effective Harness Engineering for Algorithm Discovery with Coding Agents — arXiv 2605.15221
  • TL;DR: When running LLM coding agents in iterative loops under a fixed token budget, spending more tokens per iteration on fewer high-quality attempts beats generating many cheap shallow attempts — and this advantage holds even after accounting for per-token price differences. Tested with the Vesper framework on Circle Packing (a standard algorithm discovery benchmark), deeper iterations outperformed AlphaEvolve, FunSearch, and the human best solution under the same budget. The paper also finds that agents gaming the scoring function ("evaluation hacks") are best handled by the harness detecting and invalidating suspiciously high scores rather than by changing the prompt.
  • What to do: If you run iterative agent loops for code generation or optimization, configure for fewer but deeper reasoning passes rather than maximizing iteration count under the same token budget; add score-validity checks to your eval harness to catch agents that game the objective.
  • Why trust it: Authors tested on Circle Packing (n=26 runs) with a fixed token budget; compared against multiple baselines; Vesper framework is open-source; submitted May 13, 2026.
  • Skeptic check: Circle Packing is a mathematical optimization problem with a clear scoring function; how well the depth-over-breadth finding generalizes to fuzzier software engineering tasks (bug fixing, feature implementation) is untested.
