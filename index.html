All five items today come from the Claude Code v2.1.142 release (May 14, 2026). Five distinct practitioner-relevant changes, each with a concrete action.

Agent dispatch now accepts model and permission flags

  • Source: Anthropic, Claude Code v2.1.142, May 14, 2026
  • Link: Claude Code v2.1.142 — GitHub releases
  • TL;DR: claude agents (the agent view launcher) now accepts --permission-mode, --model, --effort, --mcp-config, --plugin-dir, --settings, --add-dir, and --dangerously-skip-permissions. Every background session you dispatch from agent view starts with those settings rather than inheriting whatever defaults the target directory happens to have. The active defaults show up in the agent view footer so you know what each dispatched session will use.
  • What to do: Update to v2.1.142 (npm update -g @anthropic-ai/claude-code), then add --permission-mode plan --model opus --effort high to your claude agents launch command if you want all dispatched sessions locked to specific settings; tweak per-flag as your workflow requires.
  • Why trust it: Official Anthropic release published May 14, 2026; confirmed by Claude Code docs at code.claude.com/docs/en/agent-view and multiple third-party changelog trackers (Releasebot, ClaudeLog, ClaudeFA.st). The feature requires v2.1.142 or later — earlier versions silently ignore the flags.
  • Skeptic check: These flags set dispatch-time defaults, not hard locks; sessions still read remaining settings from the directory they run in, so one flag set cannot override every config source.

Fast mode default upgrades from Opus 4.6 to Opus 4.7

  • Source: Anthropic, Claude Code v2.1.142, May 14, 2026
  • Link: Claude Code v2.1.142 — GitHub releases
  • TL;DR: Fast mode — Claude Code's lower-latency, lower-cost response toggle — now uses Opus 4.7 as its default model instead of Opus 4.6. The change is automatic on update. Set CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE=1 to pin back to Opus 4.6 if you need reproducibility against a specific model version.
  • What to do: If you have been benchmarking fast-mode cost against Opus 4.6 pricing, rerun those calculations against Opus 4.7 rates after updating; if your evaluations or regression tests depend on Opus 4.6 output characteristics, set the override env var before updating.
  • Why trust it: Official Anthropic release; independently noted in a third-party YouTube Shorts specifically about this change, and confirmed by multiple changelog summaries.
  • Skeptic check: —

Agent threads must now report results in their final message, not .md files

  • Source: Anthropic, Claude Code v2.1.142 system prompt change, May 14, 2026
  • Link: Piebald-AI/claude-code-system-prompts — system prompt changelog tracker
  • TL;DR: Anthropic updated the agent thread system prompt in v2.1.142 to explicitly instruct agent threads to return their reports, summaries, findings, and analysis directly in their final message — rather than writing them to .md files and telling the parent agent to read the file. The same update makes file path handling uniform: agent threads now always require absolute paths unconditionally (the previous conditional for relative paths is removed).
  • What to do: If you have subagent threads that write output files and then return a file path, shift them to return the content inline in the final turn; this aligns with how Claude is now steered and avoids a pattern the system prompt actively discourages.
  • Why trust it: Confirmed by Piebald-AI/claude-code-system-prompts, which tracks every system prompt change across 179 Claude Code versions and updates within minutes of each release — the most granular independent verification available for prompt-level changes.
  • Skeptic check: This is a steering instruction in the system prompt, not an API constraint — existing agents that write files will not error out, but model behavior will drift toward inline reporting over time.

Single-file plugins now need only a root-level SKILL.md

  • Source: Anthropic, Claude Code v2.1.142, May 14, 2026
  • Link: Claude Code v2.1.142 — GitHub releases
  • TL;DR: Previously, a Claude Code plugin had to include a skills/ subdirectory to surface any skills. v2.1.142 removes that requirement: if a plugin has a SKILL.md at its root and no skills/ directory, it is automatically registered as a skill. Separately, the /plugin details pane and claude plugin details command now list any LSP servers the plugin provides.
  • What to do: Simplify single-skill plugins: move SKILL.md to the plugin root and delete the skills/ wrapper directory; run claude plugin details <name> after updating to verify the skill appears and any LSP servers are listed correctly.
  • Why trust it: Official Anthropic release; changelog entry confirmed across multiple trackers and the Claude Code docs for plugin creation.
  • Skeptic check: —

MCP_TOOL_TIMEOUT was silently capped at 60 seconds for remote servers

  • Source: Anthropic, Claude Code v2.1.142, May 14, 2026
  • Link: Claude Code v2.1.142 — GitHub releases
  • TL;DR: Setting MCP_TOOL_TIMEOUT to a value above 60 seconds had no effect on remote HTTP and SSE MCP servers — calls were hard-capped at 60 seconds regardless of the env var. v2.1.142 fixes this: the env var now actually raises the per-request fetch timeout for those server types.
  • What to do: If you have remote MCP tools that fail on long-running operations (database queries, file analysis, slow external APIs), set MCP_TOOL_TIMEOUT to your required number of seconds and update to v2.1.142 — the setting will now be honored.
  • Why trust it: Bug and fix described in the v2.1.142 changelog; this class of silent env-var misconfiguration is independently verifiable by testing tool call duration before and after updating.
