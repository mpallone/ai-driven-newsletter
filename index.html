Claude Code MCP stdio servers no longer blow up memory with debug output

  • Source: Anthropic, Claude Code CHANGELOG, May 8–9, 2026 (v2.1.136–v2.1.138)
  • Link: Claude Code releases — GitHub
  • TL;DR: If a stdio MCP server writes anything other than valid JSON-RPC to stdout — debug logs, startup banners, random print statements — Claude Code was buffering all of it indefinitely, causing sessions to climb past 10 GB RSS. That memory leak is now fixed. In the same release batch: MCP servers that connect but silently return zero tools (because tools/list fails) now retry once automatically and show connected · tools fetch failed in /mcp instead of looking healthy while being useless. Separately, the VS Code extension was failing to activate on Windows at all (v2.1.137 fix).
  • What to do: Update Claude Code (npm update -g @anthropic-ai/claude-code); if any of your MCP stdio servers write non-JSON to stdout (logging frameworks, startup messages), redirect that output to stderr so it never hits the protocol channel — the fix prevents the leak but the cleaner long-term fix is correct server behavior.
  • Why trust it: Official Anthropic CHANGELOG; specific version numbers (v2.1.136, v2.1.137, v2.1.138) confirmed from search snippets citing the GitHub releases page; exact fix description matches the issue filed in GitHub issue #33735 describing sessions reaching 18 GB. Exact version for each sub-fix not independently verified — check claude --version and the changelog directly.
  • Skeptic check: The memory fix may land in v2.1.136 (May 8) rather than v2.1.138 (May 9); the exact version boundary was not confirmed from available sources — update to latest either way.

Top LLM agents detect stale memories correctly only 55% of the time

  • Source: Hanxiang Chao, Yihan Bai, Rui Sheng, Tianle Li, Yushi Sun — arXiv:2605.06527, submitted May 7, appeared May 8–9, 2026
  • Link: STALE: Can LLM Agents Know When Their Memories Are No Longer Valid? — arXiv
  • TL;DR: Agents that maintain long-term memory fail badly when earlier stored facts are quietly invalidated by later observations — not overwritten, just made wrong. The hardest case is what the authors call "Implicit Conflict": a new message makes a stored memory wrong without ever directly saying so (e.g., "I moved to Berlin" silently invalidates a stored home address). Tested across 400 scenarios spanning 100 everyday topics with contexts up to 150K tokens, the best evaluated frontier model gets only 55.2% overall accuracy across three capabilities: detecting that a stored belief is now outdated, rejecting questions that assume the old state is still true, and applying the updated state in downstream behavior.
  • What to do: Do not rely on agents to self-diagnose when their persisted memory is stale; add explicit memory-validation steps in your harness — at re-entry points in long-running sessions, have the agent re-read relevant stored facts and check whether anything in the recent conversation contradicts them before acting.
  • Why trust it: 400 expert-validated scenarios, 1,200 evaluation queries across three probing dimensions, contexts up to 150K tokens; frontier LLMs and specialized memory frameworks both tested; submitted May 7, appeared arXiv May 8–9, 2026.
  • Skeptic check: Scenarios cover everyday topics — failure rates on structured, domain-specific agent memory (code repository state, task tracking) may differ; the benchmark does not test production harnesses that already include explicit validation logic.
