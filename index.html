Cloudflare lets agents deploy Workers with no OAuth — 60-min temporary account

  • Source: Cloudflare Developer Changelog; Simon Willison's Weblog
  • Link: Temporary accounts for AI agent deployments — Cloudflare Changelog; Simon Willison's coverage (Jun 21)
  • TL;DR: Running wrangler deploy --temporary (Wrangler 4.102.0+) deploys a live Cloudflare Worker without any account, signup, dashboard click, or API token. The deployment lives for 60 minutes; the agent also gets a claim URL that a human can open to convert the temporary account into a permanent one. While the 60-minute window is open, the agent can iterate and redeploy as many times as it needs. Supported products include Workers, Workers Static Assets, Workers KV, D1, Durable Objects, Hyperdrive, Queues, and SSL/TLS. If nobody claims within 60 minutes, everything is deleted automatically.
  • What to do: Update to Wrangler 4.102.0 and add the --temporary flag to any agent deployment step where you currently block on an OAuth handoff; surface the claim URL to the user as a post-task deliverable so they can make it permanent if they want.
  • Why trust it: Cloudflare first-party developer changelog, dated June 19, 2026; confirmed by Cloudflare blog post (blog.cloudflare.com/temporary-accounts/) and noted by Simon Willison on June 21, 2026.
  • Skeptic check: Temporary accounts are limited to the listed products — no R2, no AI Gateway, no Workers AI in the initial scope. The 60-minute window may be too short for agents doing multi-step verification before handing off to a user.

Fable 5 is free on Claude subscriptions through today only

  • Source: Anthropic; gHacks Tech News; Hacker News (item 48463982)
  • Link: Anthropic releases Claude Fable 5 free until June 22 — gHacks
  • TL;DR: Fable 5 (Anthropic's Mythos-class model, $10/$50 per million input/output tokens on the API) has been included free on Pro, Max, Team, and seat-based Enterprise plans since June 9. Access ends after June 22. From June 23, further Fable 5 use on those plans draws from usage credits billed at API rates — roughly double the price of Opus 4.8. During the free window, Fable 5 counts approximately twice as heavily against rolling rate limits as Opus 4.8, so heavy users hit their weekly cap faster.
  • What to do: Front-load any Fable 5 experiments or benchmarking tasks you've been putting off — today is the last day at no extra cost. After June 22, switch back to Opus 4.8 as your default unless the task justifies the credit cost.
  • Why trust it: Multiple corroborating primary sources: Anthropic help center, gHacks coverage dated June 10, 2026, and a widely-upvoted Hacker News thread (item 48463982) confirming the June 22 cutoff.
  • Skeptic check: The expiry applies to subscription plans (Pro, Max, Team, Enterprise). API customers pay per-token already and are unaffected by this deadline.

Codex CLI remote executors now use end-to-end encrypted Noise tunnels

  • Source: OpenAI Codex GitHub releases
  • Link: Releases — openai/codex (GitHub)
  • TL;DR: Starting in v0.141, Codex CLI remote executors connect through authenticated, end-to-end encrypted Noise Protocol relay channels — replacing unencrypted or TLS-only tunnels. Cross-platform remote execution now also preserves executor-native working directories and shells, including filesystem permission paths across app-server and exec-server boundaries. Two further alpha refinements to this feature shipped on June 21 (v0.142.0-alpha.8 and v0.142.0-alpha.9). Executor plugins can now activate their stdio MCP servers per thread, and plugin discovery adds auth-specific curated catalogs.
  • What to do: If you run Codex CLI for distributed or team-based execution (remote executors connecting to an app server), update to at least v0.141 to get the encrypted relay; note that alpha releases are not production-stable.
  • Why trust it: OpenAI first-party GitHub releases for the openai/codex repository; Releasebot June 2026 changelog summary corroborates the v0.141 feature list.
  • Skeptic check: v0.142 builds are still alpha-tagged; the encryption is implemented at the relay layer, not end-to-end across every code path, so sandbox and subprocess trust boundaries are unchanged.

Claude Code v2.1.185 doubles stream-stall wait time to 20 seconds

  • Source: Anthropic Claude Code changelog
  • Link: Claude Code changelog — Anthropic
  • TL;DR: In v2.1.185 (released June 20), the stream-stall hint now reads "Waiting for API response · will retry in …" instead of "No response from API · Retrying in …", and the timer before auto-retry fires extended from 10 seconds to 20 seconds. This reduces spurious mid-thinking retries on slow network paths. The change also prevents the previous wording from being interpreted as an error by tooling that parsed stdout for "No response from API."
  • What to do: Run claude update to get v2.1.185. If any wrapper scripts or CI steps grep Claude Code's stdout for "No response from API" to detect hangs, update those patterns to match the new wording.
  • Why trust it: Confirmed across multiple independent changelog trackers (claudeupdates.dev, llm-digest.com, polairity.io); consistent with the Anthropic official changelog.
  • Skeptic check: The 20-second wait could mask genuine connectivity outages for slightly longer before surfacing an error to the user.
